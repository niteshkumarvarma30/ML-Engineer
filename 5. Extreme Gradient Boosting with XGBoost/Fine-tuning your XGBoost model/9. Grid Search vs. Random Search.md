# Concept

## Grid Search vs. Random Search

We know that tweaking hyperparameters (like `learning_rate` and `max_depth`) can massively improve an XGBoost model.

But here is the catch: Hyperparameters interact with each other in complex, non-linear ways. You cannot just tune the `learning_rate` by itself, and then tune the `max_depth` by itself. You have to test them together as a combined recipe.

To find the ultimate recipe, we use two automated search strategies from scikit-learn: **Grid Search** and **Random Search**.

---

### 1. Grid Search (The Brute Force Method)

* **What it is:** Grid Search is an exhaustive, brute-force search. You give it a "menu" of options, and it tests *every single possible combination* on that menu.
* **The Math:** If you want to test 4 `learning_rate` options, 3 `subsample` options, and 1 `n_estimators` option, Grid Search will build and test exactly 12 distinct models ($4 \times 3 \times 1 = 12$).
* **The Pros:** It is guaranteed to find the absolute best combination on your menu.
* **The Cons (Curse of Dimensionality):** If you add too many options, the number of combinations explodes. If your grid has 400 combinations and you use 4-fold cross-validation, the computer has to train the model 1,600 times. This could take days!

---

### 2. Random Search (The Smart Shortcut)

* **What it is:** Random Search does *not* test every combination. Instead, you give it a massive menu, and you tell it exactly how many random combinations it is allowed to try using the `n_iter` parameter.
* **The Math:** You might have a grid with 400 possible combinations. If you set `n_iter=25`, the computer will close its eyes, randomly throw a dart at the menu 25 times, and only test those 25 recipes.
* **The Pros:** It is incredibly fast. Because you control `n_iter`, the search takes exactly as long as you want it to. Surprisingly, statistics prove that randomly checking 25-50 combinations will almost always find a recipe that is 99% as good as an exhaustive Grid Search!
* **The Cons:** It might technically miss the "absolute perfect" combination, but the time saved is usually well worth the trade-off.

---

### 3. Cheat Sheet: Python Code Examples

Here is how to implement both searches using XGBoost and Scikit-Learn!

*(Notice a crucial detail in the code below: Even though we might create an XGBoost `DMatrix`, Scikit-Learn search tools like `GridSearchCV` cannot read a `DMatrix`. We must pass the raw `X` and `y` directly into the `.fit()` function!)*

#### Example A: Grid Search CV

```python
import pandas as pd
import numpy as np
import xgboost as xgb
from sklearn.model_selection import GridSearchCV

# 1. Instantiate the Scikit-Learn compatible XGBRegressor
gbm = xgb.XGBRegressor()

# 2. Define the exact grid (4 x 1 x 3 = 12 combinations)
gbm_param_grid = {
    'learning_rate': [0.01, 0.1, 0.5, 0.9],
    'n_estimators': [200],
    'subsample': [0.3, 0.5, 0.9]
}

# 3. Setup the Grid Search
# cv=4 runs 4-Fold Cross Validation for every single combination
grid_mse = GridSearchCV(estimator=gbm, 
                        param_grid=gbm_param_grid, 
                        scoring='neg_mean_squared_error', 
                        cv=4, 
                        verbose=1)

# 4. Fit to the raw X and y data

# 5. Extract the winners!
print("Best parameters found: ", grid_mse.best_params_)
print("Lowest RMSE found: ", np.sqrt(np.abs(grid_mse.best_score_)))
```

#### Example B: Randomized Search CV

If we want to test a massive range of numbers, we switch to Random Search!

```python
import pandas as pd
import numpy as np
import xgboost as xgb
from sklearn.model_selection import RandomizedSearchCV

# 1. Instantiate the Scikit-Learn compatible XGBRegressor
gbm = xgb.XGBRegressor()

# 2. Define a MASSIVE grid
# np.arange(0.05, 1.05, 0.05) creates 20 different numbers.
# 20 learning rates x 20 subsamples = 400 total combinations!
gbm_param_grid = {
    'learning_rate': np.arange(0.05, 1.05, 0.05),
    'n_estimators': [200],
    'subsample': np.arange(0.05, 1.05, 0.05)
}

# 3. Setup the Random Search
# CRITICAL: We set n_iter=25 so it only randomly tests 25 of the 400 combinations!
randomized_mse = RandomizedSearchCV(estimator=gbm, 
                                    param_distributions=gbm_param_grid, 
                                    n_iter=25, 
                                    scoring='neg_mean_squared_error', 
                                    cv=4, 
                                    verbose=1)

# 4. Fit to the raw X and y data
randomized_mse.fit(X, y)

# 5. Extract the winners!
print("Best parameters found: ", randomized_mse.best_params_)
print("Lowest RMSE found: ", np.sqrt(np.abs(randomized_mse.best_score_)))
```
