## Tunable parameters in XGBoost

### Why Tune Your XGBoost Model?

Imagine you just bought a high-end sports car.
If you drive it straight off the factory lot, it is going to be incredibly fast. But if you take it to a professional mechanic who tunes the suspension, adjusts the tire pressure, and tweaks the engine specifically for the race track you are driving on today, it will be unstoppable.

XGBoost is exactly like that sports car.

---

### 1. The "Untuned" Baseline

By default, XGBoost is very powerful. If you just feed it data and tell it what Objective Function to use (e.g., `reg:squarederror`), it will build a model using its factory-default settings.

* **The Result:** In the Ames Housing dataset from your video, the untuned model was off by an average of $34,624 per house (RMSE). Not terrible, but we can do much better.

---

### 2. The XGBoost Hyperparameter Master List (Tree Dials)

When using Trees as your base learners (which you should do 99% of the time), you have a massive dashboard of hyperparameters you can tune. Here is the master list, broken down into what they actually do:

#### A. The "Structure" Dials (Controlling the Trees)
* `max_depth` **(Tree Complexity):** A positive integer. Controls how many questions each tree is allowed to ask. Lower values (e.g., 3 to 5) keep the trees simple and prevent them from memorizing the data (overfitting).
* `subsample` **(The Row Blindfold):** A decimal between 0 and 1. If set to 0.8, each tree is only allowed to look at a random 80% of the training rows. Too low = underfitting. Too high = overfitting.
* `colsample_bytree` **(The Column Blindfold):** A decimal between 0 and 1. If set to 0.3, each tree is only allowed to look at a random 30% of your features (columns). This forces the trees to be highly diverse, adding great regularization!

#### B. The "Speed" Dials (Learning Rate vs. Time)
* `learning_rate` **(Shrinkage / Eta):** Controls how aggressively the model tries to fix the residual errors. If you turn it down low (e.g., 0.1), the model learns very slowly and carefully.
* `num_boost_round` / `n_estimators` **(Number of Trees):** How many trees the factory builds. **The Trade-off:** If you set a low learning rate, you MUST compensate by giving the model more time/trees to finish the job!

#### C. The "Penalty" Dials (Regularization)
* `gamma` **(The "Worth It?" Dial):** The tree must prove that a split will drop the error by at least this amount, otherwise it refuses to grow the branch.
* `alpha` **(L1 Regularization):** The "Leaf Eraser". Forces useless leaf weights to become exactly 0.
* `lambda` **(L2 Regularization):** The "Leaf Shrinker". Smoothly shrinks large leaf weights so the model isn't too overconfident.

---

### 3. Tree Tuning vs. Linear Tuning

It is important to remember that the massive list above only applies if you are using Tree Boosters (`gbtree`).

If you decide to fire the trees and use Linear Boosters (`gblinear`), your tuning dashboard shrinks significantly. Because a linear model is just a straight math equation, you cannot tune "depth" or "subsamples."

For Linear Base Learners, you only have access to:
* `alpha` (L1 penalty on the weights)
* `lambda` (L2 penalty on the weights)
* A regularization penalty on the bias/intercept.
* `num_boost_round` (How many boosting steps to take).

---

### 4. The Result of Tuning

By simply adding three parameters (`colsample_bytree: 0.3`, `learning_rate: 0.1`, `max_depth: 5`) and increasing the number of trees (`num_boost_round=200` to compensate for the slower learning rate), the model's error dropped from $34,624 down to $29,812!

That is an almost 14% reduction in error just by tweaking a few numbers!

### 5. Cheat Sheet: Code Breakdown

Let's look at the code difference between the two models in your screenshots.

```python
import xgboost as xgb
import pandas as pd

# (Assuming X and y are already split)
housing_dmatrix = xgb.DMatrix(data=X, label=y)

# ==========================================
# MODEL 1: UNTUNED (Factory Defaults)
# ==========================================
untuned_params = {"objective": "reg:squarederror"}

untuned_cv = xgb.cv(dtrain=housing_dmatrix, 
                    params=untuned_params, 
                    nfold=4, 
                    metrics="rmse", 
                    as_pandas=True, 
                    seed=123)

# ==========================================
# MODEL 2: TUNED (Custom Suspension & Engine)
# ==========================================
tuned_params = {
    "objective": "reg:squarederror",
    "colsample_bytree": 0.3,   # Only use 30% of columns per tree
    "learning_rate": 0.1,      # Learn slowly (Shrinkage)
    "max_depth": 5             # Keep trees relatively shallow
}

# Notice we added num_boost_round=200 to give it more trees!
tuned_cv = xgb.cv(dtrain=housing_dmatrix, 
                  params=tuned_params, 
                  nfold=4, 
                  num_boost_round=200, 
                  metrics="rmse", 
                  as_pandas=True, 
                  seed=123)

# ==========================================
# PRINTING THE RESULTS
# ==========================================
# .tail(1) grabs the very last row of the CV results DataFrame 
# (which represents the final error after all the trees are built!)

untuned_rmse = untuned_cv["test-rmse-mean"].tail(1).values[0]
tuned_rmse = tuned_cv["test-rmse-mean"].tail(1).values[0]

print(f"Untuned RMSE: {untuned_rmse:.0f}")
print(f"Tuned RMSE: {tuned_rmse:.0f}")  
```

## Important Tuning Concepts

### 1. Boosting Rounds (`n_estimators` or `num_boost_round`)

In Gradient Boosting, models are built sequentially (one after the other), with each new model trying to fix the mistakes of the one before it. 

A **Boosting Round** is simply the creation of one new tree.

If you set your boosting rounds to 100, you are telling the algorithm: *"Take 100 turns. Build 100 trees, one after the other, to form our final team."*

### 2. Early Stopping (The "Auto-Stop" Feature)

Finding the perfect number of boosting rounds is tricky.
* **Too few rounds:** The model underfits (stops learning too early).
* **Too many rounds:** The model overfits (it eventually perfectly memorizes the training data and fails on new data).

**Early Stopping** is a brilliant trick that solves this automatically.

Instead of guessing the perfect number of trees, you set the boosting rounds to a massive number (like 5,000 trees). But, you also pass in a validation dataset and an `early_stopping_rounds` parameter (e.g., `early_stopping_rounds=10`).

You are effectively telling the model: *"Keep building trees, but check your score on the validation data after every single round. If your score doesn't improve for 10 rounds in a row, stop building immediately!"*

**The Analogy:** It’s like studying for a math test using practice quizzes. You keep studying and taking quizzes as long as your score goes up. But if you take 10 practice quizzes in a row and your score hasn't improved at all, you are just wasting time (and probably confusing yourself). Early stopping tells the computer to stop studying and go to sleep!

This saves massive amounts of computing time and perfectly prevents overfitting!
