# Log Normalization

In our previous lesson on Standardization, we learned that if one column has a massive variance (the numbers are highly spread out), it will act like a bulldozer and completely overpower the other columns in a machine learning model.

One of the best ways to fix this specific "High Variance" problem is using **Log Normalization**.

## 1. The Problem: The Variance Bulldozer

Look at the Pandas DataFrame in the code below. We have two columns, and we use the `.var()` method to check their variance:

```python
print(df)
```

```text
   col1   col2
0  1.00    3.0
1  1.20   45.5
2  0.75   28.0
3  1.60  100.0
```

```python
print(df.var())
```

```text
col1       0.128958
col2    1691.729167
dtype: float64
```

*   **`col1` variance:** 0.128 (Very small, tight numbers)
*   **`col2` variance:** 1691.72 (Massive, spread-out numbers)

If we feed this data into a linear model (like Linear Regression or K-Means), `col2` is going to completely dominate `col1`. The model will assume `col1` is useless just because its numbers are smaller. We need to shrink `col2` down!

## 2. The Solution: The Natural Log

To shrink `col2`, we apply a **Logarithmic Transformation**. Specifically, we use the natural log (which uses the mathematical constant $e$, roughly $2.718$).

**How the math works (ELI5):**
Instead of looking at the raw number, the natural log asks: *"What power do I have to raise $e$ to in order to get this number?"*

If your raw number is 30...
The natural log is 3.4 (because $2.718^{3.4} \approx 30$).

This math acts like a magical "squisher." It takes massive numbers and shrinks them down to small, manageable decimals, but it completely preserves the relative differences between the numbers!

## 3. Applying it in Python

Applying this in Python is incredibly easy using the `numpy` library. We just use the `np.log()` function on our offending column.

```python
import numpy as np

# Create a brand new column by applying the log transformation to col2
df["log_2"] = np.log(df["col2"])

print(df)
```

```text
   col1   col2     log_2
0  1.00    3.0  1.098612
1  1.20   45.5  3.817712
2  0.75   28.0  3.332205
3  1.60  100.0  4.605170
```

```python
# Check our new variances!
print(df[["col1", "log_2"]].var())
```

```text
col1     0.128958
log_2    2.262886
dtype: float64
```

### The Results (Leveling the Playing Field)

Look at the final output after we run the code:

*   **`col1` variance:** 0.128
*   **`log_2` variance:** 2.26

Success! The variance of our second column plummeted from $1691.7$ down to just $2.26$.
The two columns are now on a very similar, comparable scale. The bulldozer has been neutralized, and our machine learning model can now look at both features fairly.

## 4. When should you use Log Normalization?

You should reach for `np.log()` when your data meets these criteria:

*   **High Variance:** You have a specific column that is vastly more spread out than the rest of your data.
*   **Positive Numbers:** Logarithms cannot handle negative numbers or zero. Your data must exist entirely in the positive space (e.g., Prices, Heights, Time).
*   **Linear Models:** You are using a model that assumes your data is "Normally Distributed" (shaped like a bell curve). Log normalization is famous for taking skewed, messy data and pulling it into a beautiful, normal bell curve shape!
