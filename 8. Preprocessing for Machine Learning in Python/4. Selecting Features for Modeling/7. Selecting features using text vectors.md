# Selecting Features Using Text Vectors

## The Big Picture Problem

When you use TF-IDF to turn text into numbers, it creates a massive grid (matrix).

*   **Rows** are individual documents (like emails or user reviews).
*   **Columns** are every single unique word found in your entire dataset.

Because there are thousands of words, but only a few words in each specific email, your grid is mostly filled with zeros. Scikit-learn compresses this grid behind the scenes so it doesn't crash your computer.

Because it is compressed, it's really hard to just "look" at a row and see which words were actually used and what score they got. The code below is a clever trick to **un-compress a single row** so a human can read it!

Here is how the trick works, step-by-step:

---

## 1. The "Master Key" (`tfidf_vec.vocabulary_`)

When Scikit-learn first looks at all your text, it assigns an official ID number to every unique word. This acts as its column number.

For example, it might decide:
*   `'apple'` is assigned ID number `0`.
*   `'banana'` is assigned ID number `1`.
*   `'cat'` is assigned ID number `2`.

The `.vocabulary_` attribute holds this "master key" dictionary:

```python
print(tfidf_vec.vocabulary_)
```
```text
{'200': 0,
 '204th': 1,
 '33rd': 2,
 'ahead': 3,
 'alley': 4,
 ...}
```
*Note: This dictionary has absolutely nothing to do with scores or weights yet. It is purely a name tag.*

---

## 2. Looking at a Single Row

If we look at just one document (let's say the 4th document, which is row `3`), and use `.indices` and `.data`, Scikit-learn gives us two lists of numbers:

```python
print(text_tfidf[3].indices)
```
```text
[ 31 102  20  70   5 ...]
```
*   **`.indices`:** These are the Column ID numbers that actually had words in them. (e.g., column `31`, `102`).

```python
print(text_tfidf[3].data)
```
```text
[0.19392702 0.20261085 ...]
```
*   **`.data`:** These are the actual TF-IDF scores for those specific columns. Scikit-learn keeps the scores separate from the words to save memory. 

As a human, knowing that "column 31 got a 0.19" is completely useless because we don't memorize the column numbers! 

---

## 3. Flipping the Dictionary

To solve this, we take our "Master Key" and flip it backward using Python! 
Instead of `{'apple': 0}`, we flip it to `{0: 'apple'}`. 

Now, we have a translation dictionary! If we ask Python "What is word 0?", it will reply "apple".

```python
vocab = {v:k for k,v in tfidf_vec.vocabulary_.items()}

print(vocab)
```
```text
{0: '200',
 1: '204th',
 2: '33rd',
 3: 'ahead',
 4: 'alley',
 ...}
```

---

## 4. The Glue (`return_weights` function)

We don't actually touch the TF-IDF scores (from `.data`) until this final step. 

This function takes the three pieces of the puzzle and glues them together:
1. It looks at the **`.indices`** list to see which columns are used.
2. It uses the **flipped dictionary** to translate those column IDs back into readable words.
3. It grabs the actual scores from the **`.data`** list.
4. **It glues them together** into a new, readable dictionary!

```python
def return_weights(vocab, vector, vector_index):
    # Zip together the column IDs and their scores
    zipped = dict(zip(vector[vector_index].indices,
                      vector[vector_index].data))
                      
    # Translate the column IDs to words and return the final dictionary
    return {vocab[i]:zipped[i] for i in vector[vector_index].indices}
```

If we run this function on row 3, we get a beautiful, human-readable dictionary that shows exactly which words are in the document and how important they are!

```python
print(return_weights(vocab, text_tfidf, 3))
```
```text
{'and': 0.1597882543332701,
 'are': 0.26576432098763175,
 'at': 0.18599931331925676,
 ...}
```

### Why do we care? (The Feature Selection part)
Once you have this readable dictionary, you can easily sort it! If you realize a specific word has a super low score across all your documents, you can drop that word completely from your dataset to speed up your machine learning model and reduce noise!
