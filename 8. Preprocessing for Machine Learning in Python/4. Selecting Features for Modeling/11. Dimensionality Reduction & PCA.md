# Dimensionality Reduction & PCA

In previous lessons, we reduced the size of our datasets manually. We looked for columns that were missing data, had low variance, or were highly correlated, and we literally threw them in the trash.

But what if you have hundreds of columns, and none of them are obvious candidates for the trash bin? You have to use **Dimensionality Reduction**.

## 1. What is Dimensionality Reduction?

Instead of manually deleting columns, Dimensionality Reduction is an **Unsupervised Learning** method that mathematically combines and decompresses your feature space.

*   **Unsupervised learning method**
*   **Combines/decompresses a feature space**
*   **Feature extraction - here we'll use to reduce our feature space**

**The Analogy:** Imagine you have 10 different columns describing a house (Number of Windows, Number of Doors, Square Footage of the Kitchen, etc.). Instead of deleting the "Windows" column, Dimensionality Reduction mathematically squishes all 10 of those columns together into a single, brand new column called "Overall Size."

This is technically a form of **Feature Extraction** because it creates brand new features from the old ones!

## 2. The Algorithm: PCA (Principal Component Analysis)

The most famous algorithm for doing this is **PCA**.

*   **Principal component analysis**
*   **Linear transformation to uncorrelated space**
*   **Captures as much variance as possible in each component**

**How it works:** It applies a linear transformation to your data. It projects all of your features into a brand new space where they are completely uncorrelated (meaning there is zero duplicate information).

**The Variance Goal:** PCA's ultimate goal is to capture as much of the "variance" (the useful, changing information) as possible and pack it tightly into the first few new columns it creates.

## 3. How to use PCA in Scikit-Learn

Here is how we write the code and read the output:

```python
from sklearn.decomposition import PCA

# 1. Instantiate the PCA tool
pca = PCA()

# 2. Fit and Transform the data
# This does the complex math to squish the columns together
df_pca = pca.fit_transform(df)

print(df_pca)
```
```text
[[ 88.4583,  18.7764,  -2.2379, ...,   0.0954,   0.0361,  -0.0034],
 [ 93.4564,  18.6709,  -1.7887, ...,  -0.0509,   0.1331,   0.0119],
 [-186.9433, -0.2133,  -5.6307, ...,   0.0332,   0.0271,   0.0055]]
```

By default, PCA doesn't actually delete any columns. If you feed it 10 columns, it hands you back 10 brand new "Principal Components." So how do we reduce the dimensions?

### The Magic Attribute: `explained_variance_ratio_`
We have to ask the computer how much "information" it packed into each of the new columns.

```python
print(pca.explained_variance_ratio_)
```
```text
[0.9981, 0.0017, 0.0001, 0.0001, ...]
```

**How to read this:** The output is a list of percentages.
*   The first new column captured **99.81%** of all the useful information in the entire dataset!
*   The second column captured **0.17%**.
*   The third captured **0.01%**.

Because almost 100% of the information is packed into that very first component, we can safely throw the rest of the components in the trash! We just successfully reduced a massive dataset down to 1 single column!

## 4. The PCA Caveats (The Catch)

PCA is incredibly powerful, but it comes with two massive warnings:

*   **Difficult to interpret components:** Before PCA, your column was named `Square_Footage`. It was easy for a human to understand. After PCA, your column is just named `Component_1`. It is a bizarre mathematical mashup of 10 different features. It is incredibly hard to explain to your boss what `Component_1` actually represents in the real world.
*   **End of preprocessing journey:** Because PCA completely destroys your original column names and reshapes your data into abstract math vectors, you cannot do any more Feature Engineering afterward. You must finish all your missing-value imputation, standard scaling, and dummy-variable creation *before* you run PCA!
