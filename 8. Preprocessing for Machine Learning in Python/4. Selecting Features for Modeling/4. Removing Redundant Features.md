# Removing Redundant Features

The main goal of Feature Selection is to reduce "noise." If you give a machine learning model too much overlapping or unnecessary information, it gets confused and its performance drops.

One of the best ways to reduce noise is by identifying and removing **Redundant Features**.

## 1. Manual Removal (The "Common Sense" Check)

Sometimes, you don't need advanced math to find redundant features; you just need to look at the dataset and use human logic.

Look at the following scenario for manual removal:

| city | state | lat | long |
| :--- | :--- | :--- | :--- |
| hico | tx | 31.982778 | -98.033333 |
| mackinaw city | mi | 45.783889 | -84.727778 |
| winchester | ky | 37.990000 | -84.179722 |

**The Problem:** All four of these columns represent the exact same concept: Location. If a machine learning model already knows the exact GPS coordinates (`lat` and `long`), telling it the `city` and `state` adds absolutely zero new information. It is purely duplicate noise.

**The Fix:** Depending on your goal, you should manually drop either the text columns (`city`/`state`) or the math columns (`lat`/`long`).

**Another Manual Scenario:**
If you used Feature Engineering to calculate a brand new `Average_Test_Score` column from 3 individual tests, you should manually drop the original 3 test columns so you aren't feeding the model the same scores twice!

## 2. Statistically Correlated Features

Sometimes, features don't look like obvious duplicates to human eyes, but mathematically, they act like it. We call these Correlated Features.

*   **Statistically correlated:** features move together directionally
*   **Linear models assume feature independence**
*   **Pearson's correlation coefficient**

**The Problem:** If two features are highly correlated, it means they move in the exact same direction. (If Feature A goes up, Feature B goes up).

**The Danger:** Linear models assume feature independence. This means models like Linear Regression and Logistic Regression strictly expect every column to bring completely independent, unique clues. If two columns are moving in perfect sync, they act like a mathematical echo, breaking the model's rules and causing bias!

## 3. The Math: Pearson's Correlation Coefficient

To find these hidden echoes, we measure them using **Pearson's Correlation Coefficient**.
This is a math score that ranges from -1.0 to 1.0.

*   **1.0 (Strong Positive):** The features move up together in perfect sync.
*   **-1.0 (Strong Negative):** The features move in perfectly opposite directions (one goes up, the exact other goes down).
*   **0.0 (No Correlation):** The features have absolutely nothing to do with each other.

If any pair of features scores incredibly close to 1.0 or -1.0, they are highly redundant, and you should throw one of them in the trash!

## 4. How to do it in Pandas (`.corr()`)

You can calculate the Pearson score for your entire dataset instantly using the Pandas `.corr()` method!

```python
import pandas as pd

print(df)
```
```text
          A     B     C
0      3.06  3.92  1.04
1      2.76  3.40  1.05
2      3.24  3.17  1.03
...
```

```python
# The raw data has columns A, B, and C
# df.corr() generates a massive grid comparing every column to every other column!
print(df.corr())
```

```text
          A         B         C
A  1.000000  0.787194  0.543479
B  0.787194  1.000000  0.565468
C  0.543479  0.565468  1.000000
```

**How to read the output:**
Look at the intersection where row A meets column B. The score is `0.787194`.

Because 0.78 is very close to 1.0, it proves that Feature A and Feature B are strongly positively correlated. They are essentially telling the model the same story. To improve our model and reduce noise, we should pick either A or B, and completely drop the other one from our dataset!
