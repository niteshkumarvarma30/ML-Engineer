# Intro to Feature Selection

Earlier, we learned about Feature Engineering (mathematically combining or altering columns to create brand new ones).

**Feature Selection is the exact opposite.**

Instead of creating new things, Feature Selection is the process of looking at your existing dataset and deciding which columns to throw in the trash. It strictly draws from existing features and never creates new ones.

**What is feature selection?**
*   Selecting features to be used for modeling
*   Doesn't create new features
*   Improve model's performance

Why would we want to throw data away? Because giving a machine learning model too much information—especially useless information—confuses it and hurts its performance!

## 1. Automated vs. Manual Selection

There are two ways to select the best features:

*   **Automated:** Scikit-Learn has built-in math tools (like Variance Thresholds or Statistical Tests) that automatically delete weak columns for you.
*   **Manual:** This is what we are focusing on right now. Manual selection requires you (the human) to actually look at and understand the real-world context of your dataset to decide what is useful.

## 2. When to Select Features (The 3 Scenarios)

There are three main reasons you would manually drop columns from your dataset:
*   Reducing noise
*   Features are strongly statistically correlated
*   Reduce overall variance

Let's look at each scenario in detail.

### Scenario A: Reducing Noise (Redundancy)

Look at the following table representing location data:

| city | state | lat | long |
| :--- | :--- | :--- | :--- |
| hico | tx | 31.982778 | -98.033333 |
| mackinaw city | mi | 45.783889 | -84.727778 |
| winchester | ky | 37.990000 | -84.179722 |

**The Problem:** Latitude (`lat`) and Longitude (`long`) tell the computer exactly where a place is on Earth. If the model already knows the exact GPS coordinates, telling it the `city` and `state` doesn't add any new information. It just adds useless, distracting "noise" to the dataset.

**The Fix:** You must select just one way to represent location. You would either drop the GPS coordinates, or drop the city/state columns!

### Scenario B: Highly Correlated Features

Sometimes, two numeric columns are highly statistically correlated (meaning if one goes up, the other goes up in perfect sync).

**The Problem:** If you keep both columns, they act like an echo. This "echo" literally breaks the underlying math assumptions of many linear machine learning models.

**The Fix:** If you have a column for `weight_lbs` and `weight_kg`, you must drop one of them!

### Scenario C: Reducing Overall Variance (Too Many Features)

Sometimes, you just have way too many columns.

**The Problem:** If you are working with Text Vectors (TF-IDF) where every single word in the dictionary gets its own column, you might have 10,000 columns! If you have too many features, your model becomes overly complex and suffers from High Variance (Overfitting). It will memorize the training data and fail in the real world.

**The Fix:** You must use Dimensionality Reduction techniques to dramatically shrink the number of columns, keeping only the most important ones.
