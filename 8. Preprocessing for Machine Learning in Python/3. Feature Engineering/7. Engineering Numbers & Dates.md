# Engineering Numbers & Dates

Sometimes, even perfectly clean numerical data isn't quite ready for machine learning.

If data is too detailed (too granular) or highly redundant, it can confuse the model or cause overfitting. We use Feature Engineering to simplify these numbers into stronger, clearer signals.

## 1. Aggregate Statistics (The "Roll Up" Method)

Look at the following example involving temperature data (`temps`).

```python
print(temps)
```

```text
     city  day1  day2  day3
0     NYC  68.3  67.9  67.8
1      SF  75.1  75.5  74.9
2      LA  80.3  84.0  81.3
3  Boston  63.0  61.0  61.2
```

**The Raw Data:** We have a city (NYC) and the temperature recorded over three consecutive days (`day1`, `day2`, `day3`).

**The Problem:** These three columns contain basically the exact same information. Feeding all three into a model increases the dimensionality (complexity) for almost no extra benefit.

**The Solution:** We can aggregate (roll up) these numbers. Instead of giving the model three separate days, we just give it the **Average** temperature for that timeframe!

### How to do it in Pandas

To calculate the average across a horizontal row, we use the `.mean(axis=1)` function. *(Remember: `axis=1` tells Pandas to look across the columns, not down the rows!)*

```python
# 1. We use .loc to select all rows (:), and only the columns from "day1" to "day3"
# 2. We calculate the mean across the horizontal axis (axis=1)
# 3. We save the result into a brand new column called "mean"
temps["mean"] = temps.loc[:, "day1":"day3"].mean(axis=1)

print(temps)
```

```text
     city  day1  day2  day3   mean
0     NYC  68.3  67.9  67.8  68.00
1      SF  75.1  75.5  74.9  75.17
2      LA  80.3  84.0  81.3  81.87
3  Boston  63.0  61.0  61.2  61.73
```

**The Result:** The computer successfully calculates that NYC's 3-day average is 68.00. We can now drop the original 3 day columns, successfully reducing our dimensionality while keeping the core information!

## 2. Engineering Dates

Dates and times are notoriously difficult for machine learning models to handle.

Look at the `purchases` dataset.

```python
print(purchases)
```

```text
               date  purchase
0      July 30 2011    $45.08
1  February 01 2011    $19.48
2   January 29 2011    $76.09
3     March 31 2012    $32.61
4  February 05 2011    $75.98
```

**The Raw Data:** We have a date column with values like "July 30 2011".

**The Problem:** To a computer, that isn't a date. It is just a random string of text. Furthermore, a specific day in a specific year is usually way too granular (detailed). A model doesn't care that something happened exactly on the 30th of July; it probably just cares that it happened in the Summer.

### Step 1: Converting to Datetime

First, we have to force Pandas to recognize the text as an actual point in time using the magical `pd.to_datetime()` function.

```python
# Create a new column where the text dates are converted into Pandas datetime objects
purchases["date_converted"] = pd.to_datetime(purchases["date"])
```

**Output Check:** As seen in the output below, "July 30 2011" is converted into the standard computer format `2011-07-30`.

### Step 2: Extracting the Good Parts

Once a column is officially a `datetime` type, it unlocks a special superpower in Pandas: the `.dt` accessor.

This tool allows you to instantly extract the exact piece of the date you care about! If you only want the Month to see if sales spike in the summer, you just ask for it:

```python
# Extract just the month number (1 through 12)
purchases["month"] = purchases["date_converted"].dt.month

print(purchases)
```

```text
               date  purchase date_converted  month
0      July 30 2011    $45.08     2011-07-30      7
1  February 01 2011    $19.48     2011-02-01      2
2   January 29 2011    $76.09     2011-01-29      1
3     March 31 2012    $32.61     2012-03-31      3
4  February 05 2011    $75.98     2011-02-05      2
```

**The Result:** Instead of confusing the model with "July 30 2011", you just hand the model the number 7.

> [!TIP]
> **Pro Tip:** You can use `.dt.year`, `.dt.day`, or even `.dt.weekday` to engineer completely different insights from a single timestamp!
