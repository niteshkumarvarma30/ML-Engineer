# Audio Classification & Feature Extraction

In the last lesson, we learned how to load raw time series data (like an audio waveform). But how do we actually teach a machine learning model to classify it? (e.g., Is this heartbeat healthy or abnormal?)

We cannot feed a raw audio wave directly into a standard classifier like `LinearSVC`. We have to extract features first!

## 1. The Problem: Raw Audio is Too Messy

*(See your Visualize your timeseries data! screenshot)*
![Visualize your timeseries data!](../../images/visualize_timeseries.png)

That squiggly blue line is a raw audio waveform. To a computer, it is just an array of thousands of numbers (amplitudes) rapidly bouncing up and down.

If you feed that raw bouncing array into a classifier, it will be completely overwhelmed by the "noise" and fail to find any meaningful pattern. We need to simplify it!

## 2. The Solution: Summary Statistics (Feature Extraction)

![Summary Statistics](../../images/summary_statistics.png)

Instead of asking the model to look at every single tiny vibration in the waveform, we calculate Summary Statistics for the entire audio clip.

For each audio file, we calculate three simple numbers:

*   **MIN:** The lowest (quietest) point in the audio.
*   **MAX:** The highest (loudest) point in the audio.
*   **AVG (Mean):** The average volume across the whole clip.

By doing this, we take an audio file that was originally 7,000 data points long, and we crush it down into just 3 meaningful numbers! This removes the complex "time" dimension and turns the data into a standard, clean format that models like `LinearSVC` love.

## 3. Calculating Features in Python

*(See your Calculating multiple features screenshot)*
Here is how we do that math instantly for all of our audio files at once!

```python
import numpy as np

# 'audio' is a 2D array: 20 audio files, each containing 7000 data points (20, 7000)

# We use np.mean, np.max, and np.std to calculate our features.
# CRITICAL: We must set `axis=-1`. 
# This tells numpy to calculate the average ACROSS the 7000 time points for each file,
# rather than calculating the average down the 20 files!

means = np.mean(audio, axis=-1)
maxs = np.max(audio, axis=-1)
stds = np.std(audio, axis=-1)

# Now, 'means' is just a 1D array of 20 numbers!
```

## 4. Prepping for Scikit-Learn

*(See your Preparing your features for scikit-learn screenshot)*
Right now, we have three separate 1D lists (`means`, `maxs`, `stds`).
Scikit-learn requires all of our features to be neatly packed into a single 2D grid (`samples`, `features`).

We use a special NumPy tool called `column_stack` to glue these three separate lists together side-by-side!

```python
from sklearn.svm import LinearSVC

# 1. Glue our 3 features together into a clean 2D grid (our X variable)
X = np.column_stack([means, maxs, stds])

# 2. Reshape our answers (y) just in case!
y = labels.reshape(-1, 1)

# 3. Fit the classifier!
model = LinearSVC()
model.fit(X, y)
```

## Deep Dive: Understanding Audio Features

**Q: Are the mean, max, and std *added* as new features to each file of 7000 rows?**

It’s a great question! We aren't adding these features to the 7,000 points; we are completely **replacing** the 7,000 points with them.

Think of a single audio file as a book with 7,000 words. Instead of forcing the computer to read the entire 7,000-word book, we just give the computer a 3-word summary: the mean, the max, and the standard deviation (std).

So, instead of one audio file having 7,000 features, it is squished down to have exactly 3 features. This makes the data small and clean enough for a standard machine learning model to understand!

**Q: So what were those 7000 features? What do they tell us about each audio file, and how do those 3 features represent all 7000?**

That is a fantastic question! It is one of the most confusing parts of dealing with audio data.

Let's break down exactly what those 7,000 numbers are, and why we squish them into 3 numbers.

**1. What were the 7,000 data points?**
They are not traditional features like "Age," "Weight," or "Blood Pressure." They are simply **snapshots of volume over time.**

When a doctor records a heartbeat, the microphone takes thousands of tiny snapshots every single second to measure how "loud" the sound wave is at that exact millisecond.

*   Snapshot 1 (0.001 seconds): Volume is 0.05
*   Snapshot 2 (0.002 seconds): Volume is 0.12
*   Snapshot 3 (0.003 seconds): Volume is -0.04

If the recording lasts for a few seconds, you easily end up with a list of 7,000 volume snapshots. If you plot all 7,000 of those dots on a graph, they form the squiggly blue soundwave you see in the images!

**2. Why can't we just give the 7,000 points to the model?**
If you feed all 7,000 snapshots to a basic model like Logistic Regression, the model gets incredibly confused.
Why? Because a heart might "thump" at Snapshot #500 for one patient, but it might "thump" at Snapshot #3000 for another patient. The model doesn't understand that these are just shifted in time; it just sees that column 500 and column 3000 have wildly different numbers, and it fails to find a pattern.

**3. How do Min, Max, and Avg represent the whole file?**
To fix this, we stop making the computer look at individual milliseconds. We "zoom out" and look at the audio clip as a single, complete picture.

We ask 3 summary questions about the entire 7,000-piece soundwave:

*   **MAX:** "What was the absolute loudest spike (thump) in the entire recording?"
*   **MIN:** "What was the absolute lowest drop in the recording?"
*   **AVG:** "Overall, how loud was this recording on average?"

**The Trade-off:** By doing this, we completely destroy the concept of "time." The model no longer knows *when* the heart thumped. However, we capture the overall intensity and shape of the heartbeat. An abnormal, struggling heartbeat will likely have a very different Maximum volume and Average volume than a healthy heartbeat!

By summarizing it, we turned a confusing 7,000-millisecond movie into 3 clean, simple clues that a machine learning model can easily do math on.
