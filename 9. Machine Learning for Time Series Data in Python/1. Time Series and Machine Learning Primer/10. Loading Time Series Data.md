# Loading Time Series Data

Time series data comes in many different shapes and sizes. Sometimes it is a clean spreadsheet of stock prices, and sometimes it is a raw audio recording of a human heartbeat!

Because they are so different, we have to use different Python tools to load and prepare them for Machine Learning.

## 1. Handling Audio Data (The Heartbeat)

Audio is a very common type of time series data. A microphone simply records the volume/amplitude of a sound over time.

### Step A: Finding the Files (`glob`)

If you have a folder full of hundreds of `.wav` audio files, you don't want to type out every single file name. You can use Python's built-in `glob` library. By passing it a pattern like `'data/files/*.wav'`, it will automatically search your folders and return a list of every single audio file it finds!

**Example:**
```python
from glob import glob
files = glob('data/heartbeat-sounds/files/*.wav')

print(files)
```
```text
['data/heartbeat-sounds/proc/files/murmur__201101051104.wav',
 ...
 'data/heartbeat-sounds/proc/files/murmur__201101051114.wav']
```

### Step B: Reading the Audio (`librosa`)

To actually open the `.wav` file and translate the sound into math, Data Scientists use a powerful audio library called `librosa`.

**Example:**
```python
import librosa as lr
# `load` accepts a path to an audio file
audio, sfreq = lr.load('data/heartbeat-sounds/proc/files/murmur__201101051104.wav')

print(sfreq)
```
```text
2205
```

### Step C: What is Sampling Frequency (`sfreq`)?

When you load an audio file with `librosa`, it hands you back two things:

*   `audio`: A massive array of raw numbers (the actual sound wave).
*   `sfreq`: The Sampling Frequency.

In the example above, the sampling frequency is `2205`, meaning there are `2205` samples per second. This means that when the doctor recorded the heartbeat, the microphone took exactly 2,205 snapshots of the sound every single second.

**The Missing Timestamp Problem:**
Unlike a spreadsheet, an audio file doesn't come with a column of dates or times. It is just a massive list of millions of numbers. To figure out the exact timestamp for a specific sound, you have to do some math using the Sampling Frequency! (e.g., If the `sfreq` is 2205, the 2,205th number in the list happened at exactly 1.0 seconds).

**The "Dumb Text" Problem**

When you use `pd.read_csv()` to load a dataset of Apple (AAPL) stock prices, it loads the date column perfectly.
However, if you check the data types, Pandas will say it is an `object`:

```python
# We can investigate the object type of each column by accessing the dtypes attribute
df['date'].dtypes
```
```text
0    object
1    object
2    object
dtype: object
```

**The Problem:** In Pandas, `object` just means "dumb text." To the computer, "2010-01-04" isn't a date; it is just a random string of characters, no different than the word "Apple" or "Banana." If you try to plot it on a timeline, the computer won't know that January 5th comes after January 4th.

**The Fix: `to_datetime()`**

Before you can do any time series machine learning, you must force Pandas to recognize that column as actual points in time. To ensure that a column within a DataFrame is treated as time series, use the `to_datetime()` function:

```python
df['date'] = pd.to_datetime(df['date'])

df['date']
```
```text
0   2017-01-01
1   2017-01-02
2   2017-01-03
Name: date, dtype: datetime64[ns]
```

Once you run this, the data type changes from `object` to `datetime64`.
Now, Pandas unlocks its time-series superpowers! It actually understands the flow of time, allowing you to easily plot the stocks chronologically on a graph or extract the exact day of the week!
