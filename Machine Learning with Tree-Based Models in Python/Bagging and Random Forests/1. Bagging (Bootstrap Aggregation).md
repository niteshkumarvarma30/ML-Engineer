# Concept

## Bagging (Bootstrap Aggregation)

In our last lesson, we learned about the Voting Classifier. That was an ensemble where we used *different algorithms* (a Logistic Regression, a KNN, and a Decision Tree) and fed them the *same dataset*.

Bagging is the exact opposite approach.
In Bagging, we use the *exact same algorithm* (e.g., 300 Decision Trees), but we feed each of them a *slightly different dataset*!

Here is how the magic works.

---

### 1. What is Bootstrapping? (The Magic Hat)

The "B" in Bagging stands for Bootstrap. Bootstrapping is a statistical trick called **Sampling with Replacement**.

Imagine you have a magic hat with 3 balls inside: A, B, and C.
You want to draw 3 balls to make a new dataset.

* **Without Replacement (Normal way):** You draw A, keep it. You draw B, keep it. You draw C, keep it. You end up with exactly what you started with: [A, B, C].
* **With Replacement (Bootstrapping):** You draw a ball. It's B. You write it down on your notepad, and you *put the ball back in the hat*. You draw again. It's B again! You put it back. You draw again. It's A.

Your new "Bootstrapped" dataset is **[B, B, A]**.
Notice that B showed up twice, and C was left out completely!

---

### 2. Training the Ensemble (The "Jury")

Now that we know how to Bootstrap, here is how we train a Bagging Ensemble:

1. You create 300 different blank Decision Trees.
2. You use the magic hat (Bootstrapping) to create 300 slightly different versions of your training data.
3. You give Tree #1 Dataset #1. You give Tree #2 Dataset #2, and so on.

Because every tree is looking at a slightly different, scrambled version of the data, every tree grows a slightly different set of branches! You have just created a highly diverse "Jury" of 300 models.

---

### 3. The Prediction (Aggregation)

The "agging" in Bagging stands for **Aggregation** (bringing it all together).

When a brand new patient comes into the hospital, you show their data to all 300 trees. How do they make a final decision?

* **For Classification:** They take a Majority Vote. (e.g., If 250 trees say "Benign" and 50 say "Malignant", the final answer is "Benign").
* **For Regression:** They calculate the Average (Mean) of all 300 guesses.

---

### 4. Why do we do this? (Killing Variance)

Remember how we learned that a single unconstrained Decision Tree suffers from High Variance (Overfitting)? It is incredibly fragile and memorizes random noise.

**Bagging completely cures this disease.**
Because you have 300 trees that all memorized *different* random noise, when you force them to vote together, their weird mistakes cancel each other out!

The result is an incredibly robust, smooth model that is almost immune to the wild variance of a single tree.

---

### 5. Cheat Sheet: Scikit-Learn Code

Here is how you build an army of 300 trees in Python.

> [!TIP]
> We use `n_jobs=-1` to tell the computer to use every single processor core it has. Building 300 trees takes a lot of math, and this makes it run infinitely faster!

```python
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import BaggingClassifier
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score

# 1. Split the data
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=1)

# 2. Instantiate the Base Model (The single algorithm we are going to copy 300 times)
# We set a max_depth to keep the individual trees relatively simple
dt = DecisionTreeClassifier(max_depth=4, min_samples_leaf=0.16, random_state=1)

# 3. Instantiate the Bagging Classifier
# base_estimator tells it what model to copy
# n_estimators tells it how many copies to make (300)
bc = BaggingClassifier(base_estimator=dt, n_estimators=300, n_jobs=-1, random_state=1)

# 4. Fit the Ensemble to the training data
# (Scikit-learn automatically handles the Bootstrapping behind the scenes!)
bc.fit(X_train, y_train)

# 5. Predict and Evaluate
y_pred = bc.predict(X_test)
print(f"Bagging Classifier Accuracy: {accuracy_score(y_test, y_pred)}")
```
