# Concept

## Random Forests

In our previous guide, we learned about Bagging. We learned that if you train 300 Decision Trees on 300 slightly different, scrambled datasets (using the Bootstrapping "Magic Hat"), they form a highly accurate Jury that fixes the overfitting problem.

A **Random Forest** takes that exact same concept, but adds one massive, brilliant twist to force the Jury to be even more diverse!

---

### 1. The Problem with Standard Bagging

Imagine your dataset is trying to predict if a car is fast, and you have a feature called *Horsepower*. Horsepower is such an incredibly strong, obvious clue that every single one of your 300 trees is going to use it for their very first question at the Root Node.

Even though you scrambled the rows of data (Bootstrapping), all 300 trees end up looking very similar to each other because they are all obsessed with the Horsepower feature. If the trees are too similar, the Jury isn't truly diverse.

---

### 2. The Solution: Feature Sampling (The "Random" in Random Forest)

To force the trees to be different, a Random Forest adds a second layer of randomness: **Feature Sampling**.

Normally, when a tree is trying to split a node, it looks at every single feature (all the columns) to find the absolute best question to ask.

In a Random Forest, **the tree is blindfolded!**

At every single node, the tree is only allowed to look at a small, random handful of features.

* **The Math:** If your dataset has 100 features, the computer usually restricts the tree to only look at the square root ($\sqrt{100} = 10$). The tree must pick its question using *only* those 10 random features.
* At the next branch down, it grabs a *different* random handful of 10 features, and so on.

**Why this is genius:** By temporarily hiding the Horsepower feature from some of the trees, it forces those trees to look at the other, weaker clues (like Aerodynamics or Weight). You end up with 300 wildly different, highly diverse trees. When they vote together, they are incredibly robust and have even lower variance (less overfitting) than standard Bagging!

---

### 3. Feature Importance (Reading the Model's Mind)

Because a Random Forest builds hundreds of trees and tests out every single feature thousands of times, it perfectly learns exactly which features are actually useful and which are garbage.

We call this **Feature Importance**.
Every time a tree uses a feature to split a node, the computer measures how much "purer" the data got (how much the Impurity/MSE dropped). It keeps a running tally.

At the end of training, you can ask the Random Forest: *"Hey, out of all the columns I gave you, which ones actually helped you reduce the most impurity?"* The model will hand you a list of percentages (e.g., "Displacement was 40% of my decision, Weight was 30%, Color was 0%").

---

### 4. Cheat Sheet: Python Code

Here is how you build a Random Forest and plot its Feature Importances in scikit-learn!

> [!NOTE]
> Random Forests use `RandomForestClassifier` for categories, and `RandomForestRegressor` for continuous numbers.

```python
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error as MSE

# 1. Split the data

# 2. Instantiate the Random Forest
# n_estimators=400 means "Build an army of 400 trees"
rf = RandomForestRegressor(n_estimators=400, min_samples_leaf=0.12, random_state=1)

# 3. Fit the model to the training data
rf.fit(X_train, y_train)

# 4. Predict and Score
y_pred = rf.predict(X_test)
rmse = MSE(y_test, y_pred) ** 0.5
print(f"Random Forest RMSE: {rmse:.2f}")

# ==========================================
# 5. VISUALIZING FEATURE IMPORTANCE
# ==========================================

# Extract the importance scores (returns a numpy array of decimals)
importances = rf.feature_importances_

# Bind the scores to the actual column names from your dataset
# (Assuming 'X_columns' is a list of your column names)
importances_series = pd.Series(importances, index=X_columns)

# Sort the scores from lowest to highest so the graph looks neat
sorted_importances = importances_series.sort_values()

# Create a horizontal bar chart!
sorted_importances.plot(kind='barh', color='lightgreen')
plt.title("Random Forest Feature Importances")
plt.show()
```
