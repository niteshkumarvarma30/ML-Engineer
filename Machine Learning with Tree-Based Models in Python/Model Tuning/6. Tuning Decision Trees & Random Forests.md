# Concept

## Tuning Decision Trees & Random Forests

We know that models like Decision Trees and Random Forests play a game of "20 Questions" to make predictions. But how do we ensure they play the best possible game? We have to tune their settings!

---

### 1. Parameters vs. Hyperparameters

**Parameters (Learned by the Model):** These are the things the model figures out on its own during training by looking at the data.
* **Example:** The exact feature a tree decides to split on (e.g., "Weight") and the exact split-point (e.g., "> 20 lbs").

**Hyperparameters (Set by the Human):** These are the strict rules you must set *before* the training even begins. The model cannot learn these; you have to guess them.
* **Tree Hyperparameters:** The maximum depth of the tree (`max_depth`), or the minimum number of samples allowed in a leaf (`min_samples_leaf`).
* **Random Forest Hyperparameters:** Because it is an ensemble, it has extra settings like the total number of trees to build (`n_estimators`) or whether to use the magic hat (`bootstrap`).

*(Tip: You can always see a model's default hyperparameters by instantiating it and calling `model.get_params()`!)*

---

### 2. Grid Search Cross-Validation (The Brute Force Method)

Because we don't know the perfect hyperparameters in advance, we use Grid Search Cross-Validation (`GridSearchCV`).

Imagine you are at a restaurant and you want the perfect meal, but you don't know what to order.

* **The Grid (The Menu):** You create a menu of options you want to test. (e.g., Test `max_depth` of 2, 4, and 6. Test `n_estimators` of 100, 300, and 500).
* **The Exhaustive Search:** The computer orders every single combination on the menu.
* **Cross-Validation:** It tastes every meal using K-Fold Cross Validation to get a highly accurate score.
* **The Winner:** It looks at all the scores and tells you exactly which combination tasted the best!

---

### 3. The Danger: The "Cost" of Tuning

Grid search is exhaustive. If you put 10 options for parameter A, 10 for parameter B, and 10 for parameter C, the computer has to test 1,000 combinations. If you use 3-Fold CV, it has to train the model 3,000 times.

**The Problem:** Training a single Decision Tree 3,000 times is fast. Training a Random Forest (which is already an army of 400 trees) 3,000 times will take a massive amount of computing power and time.

**The Reality Check:** Hyperparameter tuning is very computationally expensive, and sometimes it only improves your model's accuracy by 1% or 2% (e.g., improving an RMSE from 3.98 to 3.89). You must always weigh the cost of the time it takes to tune vs. the actual benefit you get at the end!

---

### 4. Extracting the Best Model

When `GridSearchCV` is finally finished running, it saves the winning results inside special attributes (variables that end with an underscore `_`):

* `best_params_`: Prints out the exact winning combination (e.g., `{'max_depth': 4, 'n_estimators': 300}`).
* `best_estimator_`: This is the ultimate prize. By default, once `GridSearchCV` finds the best hyperparameters, it automatically builds a brand new model using those settings and trains it on your entire training dataset so it is ready to use!

---

### 5. Cheat Sheet: Python Code (Random Forest Regressor)

Here is how you tune a Random Forest in scikit-learn. 
*(Notice the `verbose` parameter! Because tuning a Random Forest takes a long time, turning `verbose` up will print out text messages letting you know the computer is still working and hasn't frozen!)*

```python

from sklearn.model_selection import GridSearchCV, train_test_split

    'n_estimators': [100, 300, 500],
    'max_depth': [2, 4, 6],
    'min_samples_leaf': [0.1, 0.2]
}

                       cv=3, 
                       verbose=1,

grid_rf.fit(X_train, y_train)

# 6. Extract the best results
print("Best Hyperparameters:", grid_rf.best_params_)

# 7. Extract the ultimate optimized model and test it on the unseen vault data!
best_model = grid_rf.best_estimator_

# Predict and Evaluate
y_pred = best_model.predict(X_test)
rmse_test = MSE(y_test, y_pred) ** 0.5

print(f"Final Test Set RMSE: {rmse_test:.2f}")
```
