# Concept

## Decision Trees for Regression

In the previous guide, we learned about Classification Trees (which predict categories, like "Benign" or "Malignant").

But what if you want to predict a continuous number, like the Price of a house or the Miles-Per-Gallon (MPG) of a car? You can still use a tree! We just switch to a Regression Tree.

It still plays the "20 Questions" game to split the data, but it makes two major changes to the rules.

---

### 1. The Prediction: Averages instead of Votes

In a Classification Tree, when a new data point lands in a Leaf Node, the tree takes a "majority vote" (e.g., if there are 10 Cats and 2 Dogs in the leaf, it predicts "Cat").

You can't take a majority vote with continuous numbers. 
**How a Regression Tree predicts:** When a new car's data trickles down the tree and lands in a Leaf Node, the tree simply calculates the **Average (Mean)** of all the historical cars in that leaf.

*Example:* If the leaf contains 3 cars with MPG values of 20, 22, and 24, the tree predicts 22 MPG for any new car that lands in this bucket.

---

### 2. Information Criterion: MSE instead of Gini

In a Classification Tree, the goal was to make the leaves as "pure" as possible (e.g., 100% Cats), measured by the Gini-index.

In a Regression Tree, "purity" means something different. A leaf is considered pure if all the numbers in the bucket are very close to each other.

* **Measuring Impurity:** The tree measures this messiness using **Mean Squared Error (MSE)**.

If a bucket has cars with MPGs of 21, 22, 22, 23, the MSE is very low (the numbers are tightly clustered around the average). This is a "pure" leaf!

If a bucket has cars with MPGs of 10, 25, 40, 50, the MSE is massive. This is a highly "impure" leaf.

* **The Learning Process:** Just like before, the tree exhaustively tests every possible question and chooses the one that drops the MSE the most!

---

### 3. The Superpower: Beating Linear Regression

Imagine a dataset where a car's MPG starts high, drops down in the middle, and goes back up at the end (a U-shape, non-linear curve).

* **Linear Regression:** Will fail completely. It is forced to draw a stiff, perfectly straight line through the U-shape.
* **Regression Trees:** Will succeed! Because it uses If/Else questions to chop the data into rectangular buckets, it can easily capture curvy, non-linear trends. (If you plot a Regression Tree's predictions on a graph, it actually looks like a staircase).

---

### 4. A New Hyperparameter: `min_samples_leaf`

We know that `max_depth` stops the tree from growing too tall. We introduce a second powerful constraint to stop overfitting: `min_samples_leaf`.

* **The Overfitting Problem:** If you don't constrain a Regression Tree, it will keep asking questions until every single Leaf Node contains exactly one car. It literally memorizes the training data.
* **The Fix:** If you set `min_samples_leaf = 0.1`, you are telling the tree: "You are not allowed to make a split unless the resulting leaves contain at least 10% of the total training data." This forces the buckets to stay reasonably large, preventing the model from memorizing individual outliers!

---

### 5. The Formal Mathematics

Let's translate these plain English concepts into the formal mathematical equations the computer actually uses!

#### The Prediction (The Average)

\[
\hat{y}_{node} = \frac{1}{N_{node}} \sum_{i \in node} y^{(i)}
\]

* \(\hat{y}_{node}\) **(The Prediction):** The little "hat" over the \(y\) means this is the model's prediction for anyone who lands in this specific bucket (node).
* **The Math on the right:** This is the standard formula for an Average (Mean).
    * It takes every actual real-world answer (\(y^{(i)}\)) for the data points currently sitting inside that bucket.
    * It adds them all up (\(\sum\)).
    * It divides by the total number of items in that bucket (\(N_{node}\)).

**Translation:** *"When a new car lands in this leaf, predict its MPG by just calculating the average MPG of all the historical cars in this leaf."*

#### Measuring Messiness (The MSE)

\[
I(node) = \underbrace{MSE(node)}_{mean-squared-error} = \frac{1}{N_{node}} \sum_{i \in node} (y^{(i)} - \hat{y}_{node})^2
\]

* \(I(node)\) **(Information Criterion / Impurity):** This is the "messiness" score of the bucket. The tree wants this number to be as low as possible. It sets this equal to the Mean Squared Error (MSE).
* **The Math on the right:** 
    * It looks at a real car's actual MPG (\(y^{(i)}\)) and subtracts the bucket's average prediction (\(\hat{y}_{node}\)). This tells us the Error (how far off the guess was).
    * It squares that error \((...)^2\) to make sure the penalty is positive and to heavily punish really bad guesses.
    * It adds up all those squared errors for every car in the bucket (\(\sum\)).
    * It divides by the total number of cars (\(N_{node}\)) to find the Mean (Average) Squared Error.

**Translation:** *"To figure out how pure this bucket is, calculate how far away every single car is from the bucket's average. If the cars are all clustered tightly around the average, the MSE score will be very low (a pure bucket!)."*

When the tree is deciding where to split the data, it calculates this exact top formula for every possible question, and picks the question that results in the lowest possible MSE!

### 6. Cheat Sheet: Python Code

Here is how you build a Regression Tree in scikit-learn using the `Auto-mpg` Dataset.

**Example Dataset (Auto-mpg):**

| mpg | displ | hp | weight | accel | origin | size |
|-----|-------|----|--------|-------|--------|------|
| 18.0 | 250.0 | 88 | 3139 | 14.5 | US | 15.0 |
| 9.0 | 304.0 | 193 | 4732 | 18.5 | US | 20.0 |
| 36.1 | 91.0 | 60 | 1800 | 16.4 | Asia | 10.0 |
| 18.5 | 250.0 | 98 | 3525 | 19.0 | US | 15.0 |
| 34.3 | 97.0 | 78 | 2188 | 15.8 | Europe | 10.0 |
| 32.9 | 119.0 | 100 | 2615 | 14.8 | Asia | 10.0 |

Notice that we use `DecisionTreeRegressor` instead of the Classifier!

```python
# Import DecisionTreeRegressor
from sklearn.tree import DecisionTreeRegressor
# Import train_test_split
from sklearn.model_selection import train_test_split
# Import mean_squared_error as MSE
from sklearn.metrics import mean_squared_error as MSE

# 1. Split data into 80% train and 20% test
# (Note: We do NOT use 'stratify' here, because stratify is only for categorical labels!)
X_train, X_test, y_train, y_test = train_test_split(X, y, 
                                                    test_size=0.2, 
                                                    random_state=3)

# 2. Instantiate a DecisionTreeRegressor 'dt'
# We constrain it using max_depth AND min_samples_leaf to prevent overfitting
dt = DecisionTreeRegressor(max_depth=4, 
                           min_samples_leaf=0.1, 
                           random_state=3)

# 3. Fit 'dt' to the training-set
dt.fit(X_train, y_train)

# 4. Predict test-set labels
y_pred = dt.predict(X_test)

# 5. Compute test-set MSE
mse_dt = MSE(y_test, y_pred)

# 6. Compute test-set RMSE (Root Mean Squared Error)
# We calculate MSE, then raise it to the power of 1/2 (which is the square root)
rmse_dt = mse_dt**(1/2)

# 7. Print rmse_dt
print(rmse_dt)
# Output: 5.1023068889
```
