# Concept

## Stochastic Gradient Boosting (SGB)

In our previous guide, we learned about Gradient Boosting (GB), where a team of trees sequentially plays "mini-golf," with each tree trying to predict the exact residual error left behind by the tree before it.

But standard Gradient Boosting has a hidden flaw. We fix it using Stochastic Gradient Boosting (SGB).

---

### 1. The Problem: "Exhaustive" Copycats

When a standard Gradient Boosting tree looks for the best way to split the data, it is exhaustive. It looks at every single row of data and every single feature (column) to find the absolute perfect mathematical split.

**The Flaw:** Because every tree is looking at the exact same data and the exact same features, they might all decide to use the exact same split-points! If your trees are too similar, your ensemble loses its diversity. It becomes rigid and prone to overfitting.

---

### 2. The Solution: The "Stochastic" Blindfolds

*Stochastic* is just a fancy math word for *Random*.

To force the trees to be different and diverse, we introduce two elements of randomness (very similar to the tricks we used in Bagging and Random Forests).

**Trick 1: Subsampling Rows (Data)**
Instead of giving Tree #1 all 1,000 rows of training data, we randomly grab a fraction of it (e.g., 80%, or 800 rows) *without* replacement. Tree #1 trains on those 800 rows. When Tree #2 steps up, we randomly grab a *different* 80% of the data for it to look at.

**Trick 2: Subsampling Columns (Features)**
Just like in a Random Forest, we put a blindfold on the tree. When the tree is trying to ask a question (split a node), it is only allowed to look at a random fraction of the features (e.g., 20% of the columns).

---

### 3. Why is this so powerful?

By forcing the trees to look at slightly different data and slightly different features:

* **Massive Diversity:** The trees are forced to learn different patterns, which makes the final ensemble much smarter and more robust when facing new, unseen data.
* **Lightning Fast:** Because the computer is only looking at 80% of the rows and 20% of the columns at any given step, it has to do significantly less math. SGB trains much faster than standard Gradient Boosting!

---

### 4. Cheat Sheet: Python Code

In scikit-learn, you don't need to import a new model to use Stochastic Gradient Boosting. You just use the standard `GradientBoostingRegressor` and turn on the `subsample` and `max_features` hyperparameters!

```python
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error as MSE

# 1. Split the data
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=1)

# 2. Instantiate the Stochastic Gradient Boosting model
# n_estimators=300: An army of 300 trees
# max_depth=1: Keep them as weak learners (Decision Stumps)
# subsample=0.8: (Trick 1) Each tree only gets 80% of the training rows
# max_features=0.2: (Trick 2) Each split only looks at 20% of the columns
sgbt = GradientBoostingRegressor(
    n_estimators=300, 
    max_depth=1, 
    subsample=0.8, 
    max_features=0.2, 
    random_state=1
)

# 3. Fit the model to the training data
# (It will sequentially predict the residual errors while using the random subsets!)
sgbt.fit(X_train, y_train)

# 4. Predict the Test Set
y_pred = sgbt.predict(X_test)

# 5. Evaluate using RMSE (Root Mean Squared Error)
rmse = MSE(y_test, y_pred) ** 0.5
print(f"Stochastic Gradient Boosting RMSE: {rmse:.2f}")
```
