# Choosing Components & Image Compression

In the previous guides, we explicitly told PCA how many components to keep (e.g., `PCA(n_components=2)`). But what if we don't know the magic number?

Here are two tricks to figure out exactly how many components you need, and how to use them to compress images!

## 1. The "Variance Ratio" Shortcut

Instead of blindly guessing a number, you can tell PCA exactly how much "information" you are willing to sacrifice.

If you pass a decimal number (a float between 0.0 and 1.0) into `n_components`, Scikit-Learn completely changes its behavior.

*   **The Code:** `PCA(n_components=0.90)`
*   **What it does:** You are telling the computer: "I don't care how many columns you give me back, just make sure I keep exactly 90% of the original variance!" The computer will automatically calculate the math, figure out that it takes exactly 5 components to reach 90%, and hand you back 5 components. It does the guessing for you!

## 2. The "Elbow" Trick

If you don't even know what percentage of variance you want to keep, you can use the Elbow Method (very similar to how we found k in K-Means clustering!).

1.  Run PCA without any limits so it calculates all the components.
2.  Plot the `explained_variance_ratio_` for each component on a line graph.
3.  The first few components will capture massive amounts of variance, but the line will quickly drop and flatten out.

**The Sweet Spot:** Look for the "elbow" or "kink" in the graph where the steep drop suddenly levels out. The index of that elbow is the perfect balance between reducing complexity and keeping information!

## 3. The Magic of inverse_transform

We know that `fit_transform()` takes a massive dataset and squishes it down. (e.g., 100 columns $\rightarrow$ 3 columns).

But what if you want to blow it back up to its original size? You use the `.inverse_transform()` method!

*   **How it works:** It takes your 3 compressed columns and mathematically projects them back out into the original 100-column space.
*   **The Catch (Quality Loss):** Because you permanently threw away some variance (information) during the compression step, the un-squished data will not be exactly the same as the original. It will be an approximation.

## 4. Real-World Magic: Compressing Images

Why would we ever want to squish data and blow it back up? **Image Compression!**

To a computer, a grayscale image is just a massive spreadsheet of pixel brightness values.

Imagine a face dataset where every single image is made of 2,914 pixels.

To train a model on thousands of faces, your computer has to process thousands of columns. That takes a massive amount of hard drive space and RAM.

**The PCA Compression Pipeline:**

1.  **Compress:** We run PCA and set it to keep only 290 components. PCA finds the strongest visual patterns (like shadows around eyes or the shape of a nose) and squishes the 2,914 pixels down into just 290 numbers! We just reduced our file size by 10x!
2.  **Store/Transmit:** We save this tiny file to our hard drive or send it over the internet incredibly fast.
3.  **Rebuild:** When we want to look at the picture again, we run `pca.inverse_transform()` to blow those 290 numbers back out to 2,914 pixels.

Because PCA kept the most important variances, the rebuilt picture still clearly looks like the original face! It might be slightly blurrier (quality loss), but it is a perfect trade-off for saving 90% of your disk space.
