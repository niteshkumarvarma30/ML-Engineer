# Concept

## Feature Selection vs. Feature Extraction

When you have a dataset with too many columns (high dimensionality), your machine learning models can get confused, run incredibly slowly, and suffer from overfitting.

To fix this, we have to reduce the number of columns. There are two completely different ways to do this: Feature Selection and Feature Extraction.

---

### 1. Feature Selection (The "Throw It Away" Method)

Feature Selection is exactly what it sounds like: you look at your spreadsheet, decide which columns are useful, and completely delete the rest.

**Before:**
| income | age | favorite color |
| :--- | :--- | :--- |
| 10000 | 18 | Black |
| 50000 | 47 | Blue |
| 20000 | 40 | Blue |
| 30000 | 29 | Green |
| 20000 | 22 | Purple |

**After (dropping `favorite color`):**
| income | age |
| :--- | :--- |
| 10000 | 18 |
| 50000 | 47 |
| 20000 | 40 |
| 30000 | 29 |
| 20000 | 22 |

**Why drop a column?**

*   **It's Irrelevant:** If you are trying to predict if someone will default on a bank loan, their income and age are very important. Their `favorite_color` is completely irrelevant. (As seen in your first screenshot, we just use `df.drop('favorite color', axis=1)` to throw it in the trash!).
*   **It has Zero Variance:** If every single person in your dataset is from the exact same Generation (like the Pokémon example earlier) or a column is just a constant number, it tells the computer nothing new. Drop it.
*   **It's Redundant (Perfectly Correlated):** Imagine a dataset that has a column for `weight_lbs` and a second column for `weight_kg`. They are telling you the exact same piece of information, just in different units. Keeping both is redundant and confuses models like Linear Regression. You only need one, so drop the other.

**How to spot bad columns: The Pairplot**

To find these redundant or zero-variance columns, Data Scientists use Seaborn's `pairplot()`.
If you look at your ANSUR data screenshots, `sns.pairplot()` creates a grid of scatterplots comparing every feature against every other feature.

*   **Spotting Redundancy:** When you look at the plot for `weight_lbs` vs `weight_kg`, all the dots form a perfectly straight diagonal line. This is visual proof that they are perfectly correlated duplicates!

*(Instead of a scatterplot, imagine the underlying data looking like this:)*
| weight_lbs | weight_kg |
| :--- | :--- |
| 150 | 68.0 |
| 180 | 81.6 |
| 200 | 90.7 |

*   **Spotting Constants:** When you look at the plot for the constant feature, it's just a single straight line with zero spread. No variance = useless!

*(Instead of a scatterplot, imagine the underlying data looking like this:)*
| constant | height_in |
| :--- | :--- |
| 1.000 | 70 |
| 1.000 | 65 |
| 1.000 | 72 |

### 2. Feature Extraction (The "Squish" Method)

Sometimes, you have a lot of columns that are highly correlated, but you don't want to just throw them away because they all contain a little bit of unique information.

This is where Feature Extraction comes in. Instead of throwing away columns, you mathematically combine (or extract) them into brand new, compressed columns.

**The "Tall" Analogy**

Imagine you have a dataset measuring human bodies. You have 4 columns: `arm_length`, `leg_length`, `torso_length`, and `neck_length`.
Instead of picking one and dropping the other three, Feature Extraction looks at the math and says: *"Hey, if someone has long arms, they usually have long legs and a long torso too. Let's just combine all 4 of these columns into one brand new column and call it 'Overall_Tallness'."*

**The Result**

**Before (4 Highly Correlated Features):**
| palmlength | handlength | footlength | forearmhandlength |
| :--- | :--- | :--- | :--- |
| 110 | 190 | 260 | 450 |
| ... | ... | ... | ... |

**After (Extracted down to 2 Features using PCA):**
| new feature 1 | new feature 2 |
| :--- | :--- |
| -50.2 | 12.4 |
| ... | ... |

If you look at your final screenshot, the algorithm took 4 highly correlated body measurements (`palmlength`, `handlength`, `footlength`, `forearmhandlength`) and mathematically squished them together into just 2 new columns (`new feature 1` and `new feature 2`).

You effectively reduced your dimensions in half, but you kept 96% of the original information! (The most famous algorithm for doing this is called PCA - Principal Component Analysis).

---

### 3. Summary Cheat Sheet

| Feature | Feature Selection | Feature Extraction |
| :--- | :--- | :--- |
| **The Action** | Keeps the best columns, deletes the rest. | Mathematically combines old columns to make new ones. |
| **Interpretability** | **High**: The remaining columns are still the original concepts (e.g., Age). | **Low**: The new columns are mathematical combinations (e.g., Feature 1), making them harder for humans to read. |
| **Information Loss** | **High** (You throw entire columns away). | **Low** (The math preserves the "essence" of the data). |
| **Example** | Dropping `weight_lbs` and keeping `weight_kg`. | Squishing 4 limb measurements into 1 "Size" score using PCA. |
