# Concept

## Non-negative matrix factorization (NMF)

NMF stands for "Non-negative Matrix Factorization." Like PCA, NMF is a **dimension reduction technique**. 

However, in contrast to PCA, **NMF models are interpretable**. This means an NMF model is much easier to understand yourself, and much easier to explain to others (like a business stakeholder). 

NMF achieves its interpretability by decomposing samples as sums of their parts. For example, NMF decomposes documents into combinations of common themes, and images into combinations of common patterns.

**The Catch:** NMF cannot be applied to every dataset. It is required that the sample features be entirely "non-negative" (greater than or equal to 0). This makes it perfect for word-frequency arrays, audio spectrograms, and e-commerce purchase histories.

---

## When should you use each?

### Use PCA when:
* Your main goal is dimensionality reduction while preserving as much variance as possible.
* Your data contains negative values or has been standardized/centered (e.g., using `StandardScaler`).
* You need a fast preprocessing step before training another model.
* Interpretability is less important than compression.

### Use NMF when:
* All features are strictly non-negative.
* You want human-interpretable components.
* You expect the data to be built from additive parts (topics, object parts, purchase patterns, etc.).
* Understanding the *meaning* of the learned components is more important than capturing the absolute maximum variance.

> **A Simple Analogy: Making Fruit Juice**
> 
> **PCA says:** *"I'll find the best mathematical directions to describe the flavor."*
> Those directions may involve adding and subtracting ingredients. They are optimal mathematically but not intuitive to a human.
> 
> **NMF says:** *"This juice is 60% orange, 30% mango, and 10% pineapple."*
> Those ingredients are actual, understandable parts. That's why NMF is often preferred when interpretability is the primary goal.

---

## How NMF Works (Components and Features)

Just as PCA has principal components, NMF learns **components** from the samples. 
* **Components:** The shared hidden topics/patterns learned from the entire dataset.
* **Feature Values:** The weights that tell you how strongly each individual sample (document, image, etc.) uses each component.

> **An Intuition That Often Makes it Click: A Band Playing Music**
> 
> Think of music:
> * **Components** are the instruments available in a band: 🎸 Guitar, 🥁 Drums, 🎹 Piano.
> * **Features** tell you how loudly each instrument plays in a particular song.
> 
> | Song | Guitar | Drums |
> | :--- | :--- | :--- |
> | **Song A** | 0.9 | 0.1 |
> | **Song B** | 0.2 | 1.0 |
> | **Song C** | 0.6 | 0.7 |
> 
> The instruments (components) stay the same for every song, but the volumes (features) change from song to song.

---

## Why NMF is NOT Clustering

You might think, *"So components are just clusters of the same categories?"* 
Almost correct, but a better statement is: **Components are hidden patterns (or topics), not clusters.**

* **Clustering** assigns each document to one specific group. (e.g., K-Means says a document is either Programming OR Sports).
* **NMF** lets every document be a *mixture* of multiple components. (e.g., NMF says a document is 50% Programming AND 50% Sports).

This is much more natural because real-world documents often discuss multiple topics at once!

### A simple formula to remember:
* **Component** = *"What hidden topic or pattern exists?"*
* **Feature Value** = *"How much of that topic exists in this specific document?"*

---

## Example Usage of NMF in Python

NMF is available in `scikit-learn` and follows the exact same `fit`/`transform` pattern as PCA. However, unlike PCA, **the desired number of components must always be specified**. NMF works both with NumPy arrays and sparse arrays (`csr_matrix`).

```python
# Import NMF
from sklearn.decomposition import NMF

# Create an NMF model, specifying the number of components
model = NMF(n_components=2)

# Fit the model to the non-negative samples
model.fit(samples)

# Transform the samples into NMF features
nmf_features = model.transform(samples)
```

The components learned by the model are stored in the `model.components_` attribute, and they live in the same dimensional space as the original vocabulary.

## Step 5: Reconstruction (Matrix Factorization)

Now comes the coolest part: The features and the components of an NMF model can be multiplied and added together to reconstruct the original data samples! 

This calculation is known mathematically as the "product of matrices" (which is where the **Matrix Factorization** in NMF comes from).

Suppose NMF learns these two components (Topics):
* **Programming component:** `[0.9,  0.8,  0.1,  0.0]`
* **Sports component:** `[0.0,  0.1,  0.8,  0.9]`

And suppose Document 3 has these learned Feature weights:
* **Programming weight:** `1.0`
* **Sports weight:** `0.8`

NMF says the original document can be reconstructed like this:
`Document ≈ (1.0 × Programming Component) + (0.8 × Sports Component)`

Let's calculate:
```text
  1.0 * [0.9, 0.8, 0.1, 0.0]  (Programming)
+ 0.8 * [0.0, 0.1, 0.8, 0.9]  (Sports)
-------------------------------------------
= [0.9,  0.88,  0.74,  0.72]  (Reconstructed Document)
```
*(The original document was `[1, 1, 1, 0]`. It is not perfectly identical, but extremely close! With more components, the reconstruction usually becomes more accurate).*

### The Complete Picture

Here is a visual map of how raw data is split into Components (Topics) and Features (Weights), and how multiplying them reconstructs the original data:

```text
                    ORIGINAL DATA
           Python  AI   Football  Cricket
Doc1         2      2      0        0
Doc2         0      0      2        1
Doc3         1      1      1        0
Doc4         1      2      0        0
                    │
                 NMF Learns
                    │
        ┌───────────┴────────────┐
        ▼                        ▼

  COMPONENTS (H)             FEATURES (W)
 Programming Topic        Doc1 → [2.4, 0.0]
 Sports Topic             Doc2 → [0.0, 2.2]
                          Doc3 → [1.0, 0.8]
                          Doc4 → [2.0, 0.1]
        │                        │
        └───────────┬────────────┘
                    ▼
     Reconstruct the original documents:
                 X ≈ W × H
```
