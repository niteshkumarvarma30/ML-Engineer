# Evaluating K-Means: How to Grade an Unsupervised Model

In Supervised Learning, grading a model is easy: you just compare the model's guesses against the real answers (Accuracy, RMSE, etc.). But in Unsupervised Learning, there are no real answers!

Here are the two ways we evaluate our clusters.

## 1. Cross-Tabulation (When you have a "Cheat Sheet")

Sometimes, you actually do know the real categories of your data, but you hid them from the algorithm to see if it could find them on its own. (For example, we know the real species of the Iris flowers).

To check how well the model's clusters line up with the real species, we use a Cross-Tabulation (or Crosstab) via the `pandas` library.

First, you align the labels the model predicted with the actual species list in a DataFrame:

```python
import pandas as pd

# Aligning labels and species
df = pd.DataFrame({'labels': labels, 'species': species})
print(df)
```

Then, you create the Cross-Tabulation grid:

```python
# Crosstab of labels and species
ct = pd.crosstab(df['labels'], df['species'])
print(ct)
```

It creates a simple grid:
* **Rows:** The cluster numbers the model assigned (0, 1, 2)
* **Columns:** The actual species (Setosa, Versicolor, Virginica)

If the model did a perfect job, every "Setosa" flower would fall exactly into Cluster 1, and the grid would show clean, separated numbers. If the model struggled, you would see Virginica flowers mixed across Clusters 0 and 2.

# 2. Inertia (The Ultimate Unsupervised Metric)

## K-Means Inertia (Short Notes)

## What is Inertia?

Inertia is the **Within-Cluster Sum of Squares (WCSS)**.

It measures how close all data points are to their assigned cluster centroid.

- **Lower Inertia → Better, more compact clusters**
- **Higher Inertia → Points are farther from their centroids**

---

## Formula

**Inertia (Within-Cluster Sum of Squares - WCSS)**

```text
                K
Inertia = Σ   Σ ||xᵢ − μⱼ||²
          j=1 xᵢ∈Cⱼ
```

Where:

- **xᵢ** = Data point
- **μⱼ** = Centroid of cluster *j*
- **Cⱼ** = Set of points belonging to cluster *j*
- **K** = Number of clusters
- **||xᵢ − μⱼ||²** = Squared Euclidean distance between the point and its centroid

# Step-by-Step Example

Dataset

```
2   4   5   8   10
```

Suppose K = 2

```
Cluster 1: 2, 4, 5
Cluster 2: 8, 10
```

### Step 1: Compute Centroids

```
Centroid 1 = (2+4+5)/3 = 3.67

Centroid 2 = (8+10)/2 = 9
```

---

### Step 2: Compute Squared Distances

Cluster 1

```
(2-3.67)² = 2.79
(4-3.67)² = 0.11
(5-3.67)² = 1.77

Cluster 1 Inertia = 4.67
```

Cluster 2

```
(8-9)² = 1
(10-9)² = 1

Cluster 2 Inertia = 2
```

---

### Step 3: Total Inertia

```
Total Inertia

=

4.67 + 2

=

6.67
```

---

# During Training

K-Means repeatedly performs

```
Assign Points
      │
      ▼
Compute Centroids
      │
      ▼
Compute Inertia
      │
      ▼
Move Centroids
      │
      ▼
Repeat Until Inertia Stops Decreasing
```

---

# In scikit-learn

```python
from sklearn.cluster import KMeans

kmeans = KMeans(n_clusters=2)
kmeans.fit(X)

print(kmeans.inertia_)
```

`kmeans.inertia_` returns the **final Within-Cluster Sum of Squares (WCSS)**.

---

# Important Note

As the number of clusters (**K**) increases,

```
K ↑

↓

Inertia ↓
```

Inertia always decreases when K increases.

Therefore, **Inertia alone cannot determine the best K**.

Instead, we use the **Elbow Method** to choose the optimal number of clusters.

---

# Key Takeaways

- Inertia = **Within-Cluster Sum of Squared Distances (WCSS)**.
- It measures how compact the clusters are.
- K-Means minimizes inertia during training.
- Lower inertia indicates tighter clusters.
- Inertia always decreases as K increases, so it is commonly used with the **Elbow Method**.

Most of the time, you don't have a cheat sheet. You have to grade the model using only the data itself. We do this using a metric called **Inertia**.

**What is Inertia?** It measures how "tight" or "spread out" your clusters are. Mathematically, it measures the physical distance from every single data point to the Centroid of its cluster.

* **The Goal:** Lower is better! If the inertia is a low number, it means all the data points are huddled tightly around their center pin. If the inertia is high, the cluster is spread out, loose, and messy.
* K-means actually attempts to minimize this inertia when choosing clusters.

Scikit-learn automatically calculates this for you! After you run `fit()`, it is available as the `inertia_` attribute.

```python
from sklearn.cluster import KMeans

model = KMeans(n_clusters=3)
model.fit(samples)

# Print the inertia
print(model.inertia_)
```



## 3. The "Elbow" Method: Choosing the right k

When you set up K-Means, you have to tell the computer how many clusters to look for (`n_clusters=3`). But what if you are looking at raw customer data and have no idea how many clusters exist?

You use the **Elbow Method**.

1. You run a `for` loop that tests K-Means models with 1 cluster, then 2 clusters, then 3, 4, 5, etc.
2. For every model, you record its Inertia score.
3. You plot these scores on a line graph.

* **The Catch:** As you add more clusters, the inertia will always go down. (If you have 100 customers and create 100 clusters, every customer has their own pin. The distance is 0, so inertia is 0. But 100 clusters is completely useless for business!).
* **The Solution:** You look at the line graph for the **"elbow"**—the exact point where the line stops dropping rapidly and starts leveling off. That "elbow" point is the perfect sweet spot between having tight clusters and not having too many groups!

# 1. What is K-Means?

K-Means is an **unsupervised machine learning algorithm**.

Its objective is to group similar data points into **K clusters**.

Unlike classification,

K-Means does **not** know the correct answers.

It simply groups similar observations based on feature similarity.

Example

```
Students

↓

Group similar students

↓

Cluster 0

Cluster 1

Cluster 2
```

---

# 2. Is K-Means Supervised or Unsupervised?

K-Means is an **Unsupervised Learning Algorithm**.

This means

```
No Target Variable

No Labels

No Ground Truth
```

Example Dataset

| CGPA | Aptitude |
|------|----------|
|8.5|90|
|8.0|88|
|5.5|55|
|5.8|60|

Notice

There is **no output column**.

The algorithm only receives

```
CGPA

Aptitude
```

and tries to discover natural groups.

# 5. What is Cross Tabulation?

Cross Tabulation (Contingency Table)

is a method of comparing

```
Actual Class

vs

Predicted Cluster
```

It is **not part of the K-Means algorithm**.

Instead,

it is used **after training** to evaluate clustering quality.

---

# 6. Why Do We Use Cross Tabulation?

Suppose we already know the true labels

(for educational purposes).

After K-Means finishes,

we compare

```
Actual Labels

↓

Cluster Labels
```

If both are similar,

the clustering is good.

# 14. Python Example

```python
import pandas as pd
from sklearn.cluster import KMeans

# Feature Matrix
X = df[['CGPA', 'Aptitude']]

# Actual Labels (Not Used During Training)
y = df['Placement']

# Train K-Means
kmeans = KMeans(n_clusters=2, random_state=42)
kmeans.fit(X)

# Predicted Cluster IDs
clusters = kmeans.labels_

# Cross Tabulation
print(pd.crosstab(y, clusters))
```

---

# Key Takeaways

- K-Means is an **unsupervised learning** algorithm.
- It **never uses the target labels** during training.
- Cross Tabulation is **not part of the K-Means algorithm**.
- Cross Tabulation is an **evaluation technique** performed **after** clustering.
- Cross Tabulation can only be used if the dataset has **true labels** available.
- Cluster IDs (0, 1, 2, ...) are **arbitrary** and do not represent class names.
- If no true labels exist, clustering should be evaluated using metrics such as **Inertia**, **Silhouette Score**, **Davies-Bouldin Index**, or **Calinski-Harabasz Index**.
