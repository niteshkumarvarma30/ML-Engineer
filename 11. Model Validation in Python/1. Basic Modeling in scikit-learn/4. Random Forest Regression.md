# Random Forest Regression

In previous lessons, we used Random Forests for Classification (predicting a category like "Sick" or "Healthy").

Now, we are looking at Regression Models—models built to predict continuous numbers (like House Prices or Student Debt). Here is exactly how a Random Forest Regression model works!

## 1. The Building Block: Decision Trees

Before we can build a forest, we have to look at a single tree.
A Decision Tree plays a game of "20 Questions" to split the data.

Look at your Decision trees screenshot (image_38383e.png).
Imagine we want to predict how much debt a student named Bob has.

*   **The Path:** Bob is Left-Handed (Yes), he is 18 years old (Age > 15), and he likes onions (Yes).
*   **The Leaf Node:** Bob's data trickles down the branches until he lands in an end-node (a "leaf").
*   **The Prediction:** Because this is a Regression tree, it can't take a "majority vote". Instead, it looks at all the historical people in its training data who landed in that exact same leaf, and calculates their Average. It predicts Bob has $4,000 of debt.

## 2. The Forest: Averaging Decision Trees

A single decision tree is fragile and prone to making weird mistakes. To fix this, we build a Random Forest.

Look at your Averaging decision trees screenshot (image_38387f.png).
Instead of relying on one tree, the computer builds 5 completely different trees. They all look at Bob, and they all make a slightly different guess:

*   Tree 1: $4,000
*   Tree 2: $3,900
*   Tree 3: $5,100
*   Tree 4: $4,000
*   Tree 5: $4,000

**The Final Prediction:** The Random Forest simply takes the Mean (Average) of all the trees! The final, highly accurate prediction for Bob is $4,200.

> [!NOTE]
> 🚨 **Wait, is this Boosting?**
> No! This technique of building many independent trees at the same time and averaging their answers is called Bagging (Bootstrap Aggregating).
>
> In a Boosting algorithm (like XGBoost or Gradient Boosting), the trees are built sequentially (one at a time). Instead of just averaging independent guesses, Tree #2 is specifically built to fix the exact mistakes made by Tree #1!

## 3. Controlling the Forest (Parameters)

Look at the Random forest parameters screenshot (image_383c3b.png).
When you create the model in scikit-learn, you can control how the forest grows by setting three main parameters:

*   `n_estimators`: How many trees should the forest build? (e.g., 50).
*   `max_depth`: How many questions is each tree allowed to ask before it is forced to stop? (e.g., 5 questions deep). This stops the trees from memorizing the data!
*   `random_state`: Because the forest relies on randomness to build different trees, setting a seed (like 1111) locks the randomness. If you run the code again tomorrow, you will get the exact same results.

```python
from sklearn.ensemble import RandomForestRegressor

# Setting the parameters when initiating the model
rfr = RandomForestRegressor(n_estimators=50, max_depth=5, random_state=1111)

# You can also change them later!
rfr.n_estimators = 50
```

## 4. Reading the Model's Mind (Feature Importance)

Once the model is finished training, how do we know which clues were actually helpful? We can ask the model using the `.feature_importances_` attribute!

Look at the Feature importance screenshot (image_383c7c.png).
Every time a tree uses a feature (like Age or Eye Color) to split the data, it keeps a running tally of how helpful that feature was. At the end, it outputs a percentage score for every column.

```python
# Loop through the column names and their importance scores
for item in zip(X.columns, rfr.feature_importances_):
    print("{1:10.4f} - {0}".format(item[0], item[1]))
```

**The Output:**

*   `left_handed`: 0.8350
*   `age`: 0.1510
*   `likes_onions`: 0.0120

**The Verdict:** The model is telling us that being left-handed contributed to 83.5% of its decision-making power! Meanwhile, `likes_onions` basically didn't matter at all. If we wanted to, we could delete the "likes_onions" column from our dataset to make the model faster and simpler!
