# Intro to Model Validation

You have built a machine learning model, but how do you know if it is actually any good?

Model Validation is the process of testing your model to ensure it performs exactly as expected when you release it into the real world. Here is a breakdown of the basics!

## 1. What is Model Validation?

In the real world, the ultimate goal of a machine learning model is to make accurate predictions on new data.

If you build a model to predict house prices, you don't care if it can guess the price of a house that was already sold last year. You care if it can guess the price of a brand new house going on the market tomorrow!

*   **The Holdout Set:** To validate our model, we must test its accuracy on data it has never seen before. We do this by setting aside a chunk of our data in a vault (called a holdout set or a testing set).
*   **The Goal:** If your model scores just as well on the holdout data as it did on the training data, your model is successfully validated!

## 2. The Scikit-Learn Modeling Review

Look at your screenshots detailing the scikit-learn review (scikit-learn modeling review and Modeling review continued). No matter what model you use, validation always follows this simple 4-step workflow:

### Step 1: Create the Model

You choose your algorithm (in this case, a Random Forest) and set its parameters.

```python
from sklearn.ensemble import RandomForestRegressor
model = RandomForestRegressor()
```

### Step 2: Fit the Model (Training)

You hand the model your features (X) and your answers (y) so it can study the patterns.

```python
model.fit(X, y)
```

### Step 3: Predict

You hand the model new data and ask it to generate guesses.

```python
predictions = model.predict(X_test)
```

### Step 4: Assess Accuracy (Validation)

You compare the model's guesses (`predictions`) to the actual true answers (`y_test`). In this example, we use Mean Absolute Error (MAE) to see exactly how far off our predictions were on average.

```python
from sklearn.metrics import mean_absolute_error
error = mean_absolute_error(y_test, predictions)
```

## 4. The Danger: Seen vs. Unseen Data

Look at your final screenshot (Seen vs. unseen data).

Machine learning models are like students taking a test. They will always perform better on the practice test (Seen/Training Data) than they do on the final exam (Unseen/Testing Data).

*   **The Overfitting Trap:** If a model memorizes the training data, its training error will be close to zero. But when you test it on unseen data, its testing error will be massive!
*   **The Diagnosis:** If your Training Error and Testing Error are vastly different, your model is overfitted.

The entire point of Model Validation is to tune your parameters, pick the right algorithms, and choose the right metrics so that you get the absolute lowest Testing Error possible!
