# Train, Validation, and Test Splits

In our previous lessons, we learned the "Golden Rule" of Machine Learning: Never test your model on the same data it used to study. If you do, the model just memorizes the answers, and your accuracy scores will be fake.

To enforce this rule, we have to slice our original dataset into different buckets. Here is exactly how we do it using Scikit-Learn!

## 1. Preparing the Data (X and y)

Before we can split anything, we have to separate our "clues" from our "answers."

In this lesson, we use the Tic-Tac-Toe dataset. Let's visualize what this looks like in a table format:

**The Tic-Tac-Toe Dataset**

| Top-Left | Top-Mid | Top-Right | Mid-Left | ... | Bottom-Right | Winner (y) |
|---|---|---|---|---|---|---|
| X | b | O | X | ... | O | positive (X won) |
| O | O | X | b | ... | X | negative (X lost) |
| X | X | X | O | ... | b | positive (X won) |

*(Note: "b" means the square is blank).*

*   **The Features (X):** The first 9 columns showing where the X's and O's are.
*   **The Target (y):** The final 10th column indicating whether Player 1 (X) won or lost.

## 2. The Traditional Train/Test Split (80/20)

The standard rule of thumb for Machine Learning is an 80/20 split.

You use 80% of the data to train the model, and you lock the remaining 20% in a vault as the "Unseen" Test Set.

How to code it in Scikit-Learn:

```python
from sklearn.model_selection import train_test_split

# test_size=0.20 tells it to lock 20% in the vault.
# random_state ensures we get the exact same shuffle every time we run the code!
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.20, random_state=1111)
```

## 3. The Problem: Parameter Tuning

Wait, what if you want to test out different hyperparameters?
For example, what if you build one Random Forest with 100 trees, and a second Random Forest with 1,000 trees, and you want to see which one is better?

*   **The Trap:** You might think, "I'll just test them both on the Test Set!"
*   **The Rule:** NO! The Test Set is completely off-limits until you are 100% finished building your model. If you use the Test Set to help you pick your parameters, information from the test has "leaked" into your decision-making process!

## 4. The Solution: The Validation Set

To test parameters safely, we need a third bucket of data: The Validation Dataset.

We now have three buckets:

1.  **Training Set:** Used to study the data.
2.  **Validation Set:** Used to take "Practice Quizzes" so you can tune your parameters (like testing 100 vs. 1000 trees).
3.  **Test Set:** The "Final Exam" locked in the vault, used only once at the very end.

### The 60 / 20 / 20 Math

To get three buckets, we simply use the `train_test_split()` function twice.

Here is how the math breaks down in the code below:

*   **First Split:** We take the original 100% and slice off 20% for the Final Test Set. We are left with a temporary training set of 80%.
*   **Second Split:** We take that 80% and slice it using a 75/25 ratio. (Why? Because 25% of 80 is exactly 20!).
*   **Final Result:** 60% Train, 20% Validation, 20% Test!

**The "Double Split" Code:**

```python
# SPLIT 1: Slice off the 20% Final Test Set
X_temp, X_test, y_temp, y_test = train_test_split(X, y, test_size=0.20, random_state=1111)

# SPLIT 2: Slice the remaining 'temp' data into Training (75%) and Validation (25%)
# (25% of the 80% temporary data equals exactly 20% of the total data!)
X_train, X_val, y_train, y_val = train_test_split(X_temp, y_temp, test_size=0.25, random_state=1111)

# Now we safely have our 3 distinct datasets!
```
