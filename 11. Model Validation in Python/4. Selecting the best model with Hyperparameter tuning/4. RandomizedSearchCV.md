# RandomizedSearchCV

When we want to tune a machine learning model, we have to test different hyperparameters (like the number of trees or the maximum depth). But how do we decide which combinations to test?

Here is why data scientists use Random Search instead of standard Grid Search.

## 1. The Problem with Grid Search (The Time Explosion)

*(Look at your Grid searching hyperparameters and Grid searching continued screenshots).*

A Grid Search is a brute-force method. It tests every single possible combination of the hyperparameters you give it.

If you have 5 options for the number of trees, and 4 options for the maximum depth, Grid Search builds 20 different models ($5 \times 4 = 20$).

**The Danger:** If you add just a few more parameters, the training time grows exponentially.
If you want to test 4 depths, 9 max features, and 9 split options, Grid Search has to train 324 models ($4 \times 9 \times 9 = 324$). If you are using 5-fold Cross-Validation, the computer actually has to train 1,620 models ($324 \times 5$). This could take hours or days!

## 2. The Solution: Random Search (RandomizedSearchCV)

*(Look at your Random search screenshot).* We can skip the brute-force method and use Scikit-Learn's `RandomizedSearchCV`.

Instead of testing all 324 combinations, Random Search puts all the options into a hat. It randomly draws a combination, tests it, and repeats.

**The Magic:** You get to tell the computer exactly when to stop! Even though there are 324 possible combinations, you can tell Random Search to just pick 40 random combinations. Statistically, randomly testing 30 or 40 models will almost always find a "winning" combination that is just as good as the one found by the 324-model Grid Search, but in a fraction of the time!

## 3. How to Set It Up (The Parameters)

*(Look at the Random search parameters and Setting RandomizedSearchCV parameters screenshots).* To use this tool, you have to define a few specific arguments:

*   `estimator`: The base model you are trying to tune (e.g., `RandomForestRegressor()`).
*   `param_distributions`: The dictionary menu of hyperparameters you want it to randomly pick from.
*   `n_iter`: The number of random combinations you want it to test! (e.g., `n_iter=40` means it will only guess and check 40 times).
*   `cv`: The number of cross-validation folds. (This is why it has "CV" in the name! It uses the gold-standard cross-validation to grade every random guess).
*   `scoring`: The grading rubric (e.g., Mean Absolute Error).

## 4. Cheat Sheet: Python Code

Here is exactly how we implement this time-saving tool in Python!

```python
from sklearn.model_selection import RandomizedSearchCV
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import make_scorer, mean_absolute_error

# 1. Instantiate the base model
rfr = RandomForestRegressor(random_state=1111)

# 2. Define the hyperparameter menu (The 'distributions')
# (4 depth options x 9 features x 9 split options = 324 possible combinations)
param_dist = {
    'max_depth': [2, 4, 6, 8],
    'max_features': [2, 4, 6, 8, 10, 12, 14, 16, 18],
    'min_samples_split': [2, 4, 6, 8, 10, 12, 14, 16, 18]
}

# 3. Create a custom scorer (MAE)
mae_scorer = make_scorer(mean_absolute_error)

# 4. Instantiate RandomizedSearchCV
# We set n_iter=40 so it only tests 40 out of the 324 combinations!
random_search = RandomizedSearchCV(estimator=rfr, 
                                   param_distributions=param_dist, 
                                   n_iter=40, 
                                   cv=5, 
                                   scoring=mae_scorer, 
                                   random_state=1111)

# 5. Fit to the training data
# The computer will now randomly guess and check 40 times using 5-Fold CV.
random_search.fit(X, y)

# When it's done, you have a highly optimized model that trained in record time!
```
