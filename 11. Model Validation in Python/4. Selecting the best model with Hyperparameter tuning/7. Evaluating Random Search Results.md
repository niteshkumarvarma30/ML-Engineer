# Evaluating Random Search Results

In our last lesson, we used `RandomizedSearchCV` to randomly test 40 different combinations of hyperparameters for a Random Forest model.

When you type `random_search.fit(X, y)`, the computer goes to work. But when it finishes, it doesn't automatically print out a massive report. It quietly saves all the results inside the `random_search` object.

Here is how you dig into that object to find the winning model!

## 1. Finding the Winner (`best_score_` and `best_params_`)

*(Look at the first screenshot: image_89f17f.png).* The easiest way to see who won the 40-model bake-off is to ask for the "best" attributes.

*(Note: Any attribute that ends with an underscore `_` means it was generated AFTER you ran `.fit()`!)*

*   `rs.best_score_`: This prints out the cross-validation score of the winning model. (In the screenshot, the best Mean Absolute Error was 5.45).
*   `rs.best_params_`: This prints a dictionary showing the exact recipe used to build the winning model. (e.g., `{'max_depth': 4, 'max_features': 8, 'min_samples_split': 4}`).

## 2. Getting the Winning Model (`best_estimator_`)

Knowing the winning score is great, but what if you actually want to use the model right now to predict real data?

*(Look at the Selecting the best model screenshot: image_89f4a3.png).*

You don't have to manually build a new Random Forest and type in those winning parameters. `RandomizedSearchCV` already did it for you!

It saves the ultimate, fully-trained winning model inside the `best_estimator_` attribute.

```python
# Extract the winning model
winning_model = random_search.best_estimator_

# You can immediately use it to make predictions on new data!
predictions = winning_model.predict(new_data)
```

## 3. Deep Dive into the Data (`cv_results_`)

What if you want to see how all 40 models performed, not just the winner?

*(Look at the Other attributes screenshot: image_89f445.png).* Every single piece of math the computer did is stored in a massive dictionary called `cv_results_`.

*   `rs.cv_results_['mean_test_score']`: This returns an array of 40 scores (one for every model tested).
*   `rs.cv_results_['params']`: This returns a list of 40 dictionaries showing the exact parameters used for each of those 40 tests.

**Why look at the losers?**

*(Look at the Using .cv_results_ screenshot: image_89f465.png).*
You can put this massive dictionary into a Pandas DataFrame to find overarching trends!

In the example, the instructor grouped all the scores by Max Depth.

*   **The Insight:** Models with a max depth of 2.0 got terrible scores (around 0.67). But models with a max depth of 10.0 got great scores (around 0.89).
*   **The Action:** This tells you that deeper trees are significantly better for this specific dataset. If you decide to run another Random Search later, you can completely remove shallow trees from your menu to save time!

## 4. Comparing Different Algorithms

*(Look at the Comparing types of models screenshot: image_89f4c1.png).*

Random Search helps you find the best version of a single algorithm (like finding the best Random Forest). But what if you aren't sure if a Random Forest is the right tool for the job at all?

You can run a Random Search on a Random Forest (`rfr`), and a completely separate Random Search on a Gradient Boosting model (`gb`).
Once both searches are done, you grab the `best_estimator_` from both, and race them against each other on your final, hidden Test Set!

```python
# The Random Forest's final test score
print(rfr.score(X_test, y_test)) # Output: 6.39

# The Gradient Boosting final test score
print(gb.score(X_test, y_test))  # Output: 6.23
```

Because Gradient Boosting achieved a lower error (6.23) on the completely unseen test data, you crown it the ultimate champion and deploy it to the real world!
