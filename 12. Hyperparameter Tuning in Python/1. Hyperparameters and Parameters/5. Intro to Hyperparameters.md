# Intro to Hyperparameters

In the previous lesson, we learned about Parameters (like the coefficients in Logistic Regression). Parameters are the math numbers that the model learns completely on its own by studying the data.

Now, we are going to look at Hyperparameters.

## 1. What is a Hyperparameter?

*(Look at the What is a hyperparameter screenshot).* Think of a machine learning model like an old-school radio.

Hyperparameters are the knobs and dials on the front of the radio.

*   **The Rule:** You (the data scientist) must physically turn these dials and set them before the model starts training. The algorithm does not and cannot learn these on its own!
*   **The Goal:** You "tune" these dials in different combinations, hoping that a beautifully accurate model comes out the other side.

## 2. Exploring a Model's Dials

How do you know what dials a model has? You just instantiate a blank model and print it out!

*(Look at the Hyperparameters in Random Forest and Hyperparameters in Logistic Regression screenshots).*

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression

# Print the Random Forest dials
rf_clf = RandomForestClassifier()
print(rf_clf) 
# Output shows DOZENS of dials: n_estimators, max_depth, min_samples_leaf, etc.

# Print the Logistic Regression dials
log_reg_clf = LogisticRegression()
print(log_reg_clf)
# Output shows FAR FEWER dials: C, penalty, solver, etc.
```

**The Takeaway:** Some algorithms (like Random Forests) are incredibly complex and have a massive dashboard of hyperparameters to tune. Simple linear models (like Logistic Regression) have far fewer.

## 3. How to Set Hyperparameters

*(Look at the A single hyperparameter and Setting hyperparameters screenshots).*

If you don't touch the dials, Scikit-Learn will just use its factory default settings. For example, the default for `n_estimators` (the number of trees in a Random Forest) used to be 10.

If you want to change it, you simply pass your new numbers as arguments when you create the model:

```python
# We manually override the factory defaults!
# We set the number of trees to 100, and change the math criterion to 'entropy'
rf_clf = RandomForestClassifier(n_estimators=100, criterion='entropy')
```

*(**Pro Tip:** If you don't know what a hyperparameter does, check the Scikit-Learn documentation! It will give you the definition, the data type it expects, and the default value).*

## 4. Hyperparameter Importance (The "Dummy" Dials)

*(Look at the Hyperparameter Importance screenshot).*

Here is a massive secret: Not all hyperparameters actually affect your model's accuracy!
Some of the dials on the dashboard are purely administrative. You shouldn't waste time "tuning" them to get a better score.

**Examples of Administrative Hyperparameters:**

*   `n_jobs`: Tells the computer how many CPU cores to use. (Only speeds up the training time; doesn't make the model smarter).
*   `random_state`: Sets the random seed so your results are reproducible tomorrow.
*   `verbose`: Tells the computer how much text to print out on your screen while it's thinking.

## 5. The VIP Dials for Random Forests

*(Look at the Random Forest: Important Hyperparameters screenshot).* If you are tuning a Random Forest, these are the dials you should focus your energy on:

*   `n_estimators`: The number of trees. Generally, you want to set this high (e.g., 500 or 1,000) for a robust model, though it takes longer to compute.
*   `max_features`: How many columns each tree is allowed to look at. Tuning this is vital for ensuring your trees are diverse!
*   `max_depth` & `min_samples_leaf`: These are your brakes. You tune these to stop the trees from growing too deep and overfitting your data.
*   `criterion`: (e.g., `'gini'` vs `'entropy'`). This changes the math the tree uses to split data. It usually only has a minor impact on performance.

## 6. How do I learn what to tune?

*(Look at the final screenshot: How to find hyperparameters that matter?).*

Every algorithm has different dials. How do you learn which ones actually matter?

*   **Academic Papers:** Researchers often test millions of combinations and publish exactly which dials work best for specific algorithms.
*   **Blogs & Tutorials:** Sites like DataCamp or Towards Data Science are filled with cheat sheets for tuning.
*   **Scikit-Learn Documentation:** The official manual explains what every dial does.
*   **Experience:** The more you practice running Grid Searches and Random Searches, the faster you will build an intuition for which dials actually move the needle!
