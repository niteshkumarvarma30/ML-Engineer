# RandomizedSearchCV in Scikit-Learn

We already know the mathematical "Probability Trick" that proves Random Search can find a winning model by only testing a fraction of the total combinations.

Now, it is time to write the code. The best part? If you already know how to write a GridSearchCV, you already know how to write a RandomizedSearchCV!

## 1. Comparing Grid Search to Random Search

*(Look at the Comparing Scikit Learn Modules screenshot).*
The code for both methods is almost perfectly identical. They both require:

*   An algorithm (the estimator).
*   A cross-validation scheme (`cv`).
*   A scoring metric (`scoring`).

There are only two key differences you need to change in your code:

**Difference A: `param_distributions` instead of `param_grid`**
*   In Grid Search, you give the computer a rigid grid of numbers.
*   In Random Search, you provide a "distribution" (a menu) of numbers to randomly sample from.
*(Note: If you just pass standard Python lists into this dictionary, Scikit-Learn will default to "Uniform Sampling" (meaning every number in your list has an equal chance of being blindly picked out of the hat).*

**Difference B: `n_iter` (The Most Important Dial)**
Because you aren't testing every single combination, you have to tell the computer exactly when to stop guessing.
`n_iter` stands for "Number of Iterations".
If you set `n_iter=10`, the computer will only draw 10 random recipes from the hat, build 10 models, and stop.

## 2. Building the RandomizedSearchCV Object

*(Look at your Build a RandomizedSearchCV Object screenshots).* Here is exactly how we set up the distributions and instantiate the searcher!

```python
from sklearn.model_selection import RandomizedSearchCV
from sklearn.ensemble import GradientBoostingClassifier
import numpy as np

# 1. Create lists of options for our dials
# np.linspace gives us 50 evenly spaced decimals between 0.0001 and 10!
learn_rate_list = np.linspace(0.0001, 10, 50)
min_samples_leaf_list = range(1, 51)

# 2. Build the parameter dictionary
# Note the name change to 'param_distributions'!
param_dist = {
    'learning_rate': learn_rate_list,
    'min_samples_leaf': min_samples_leaf_list
}

# 3. Instantiate the Random Search Object!
# We set n_iter=10 so it only tests 10 random combinations!
random_search = RandomizedSearchCV(
    estimator=GradientBoostingClassifier(),
    param_distributions=param_dist,
    n_iter=10,
    cv=5,
    scoring='accuracy'
)

# 4. Run the search
random_search.fit(X_train, y_train)
```

## 3. Analyzing the Output (The "Patchy" Coverage)

*(Look at your Analyze the output screenshots).*

The amazing thing about `RandomizedSearchCV` is that its output object is exactly the same as `GridSearchCV`.
This means you can use the exact same shortcuts we learned earlier to find the winner:

*   `random_search.best_params_`
*   `random_search.best_score_`
*   `random_search.cv_results_`

**Visualizing the Random Guesses**

If you dig into the `cv_results_` dictionary and plot the 10 combinations that the computer randomly chose to test, what does it look like?

*(Look at the final scatterplot in your screenshots).*

Instead of a perfect, uniform grid of dots, you get a patchy, scattered cloud of dots.

Even though there are only 10 dots, notice how they are spread out all over the graph! The search covered a massive area of possibilities (from very low to very high learning rates) using a tiny fraction of the computational time.

This patchy coverage is exactly how Random Search successfully hunts down the best hyperparameters in record time!
