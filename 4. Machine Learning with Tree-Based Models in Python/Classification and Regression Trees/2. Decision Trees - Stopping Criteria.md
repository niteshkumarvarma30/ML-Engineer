# 1. Why Do We Need Stopping Criteria?

So far, we know that a Decision Tree is built using the following process:

```
Dataset

↓

Find Best Split

↓

Split Dataset

↓

Find Best Split Again

↓

Split Again

↓

Repeat...
```

Now an important question arises:

> **When should the Decision Tree stop growing?**

If we never stop the algorithm, it can continue splitting until every leaf contains only **one training sample**.

This creates a very large tree that memorizes the training data instead of learning useful patterns.

---

# 2. What Happens if the Tree Never Stops?

Suppose we have the following dataset.

| Student | Marks | Result |
|----------|-------|--------|
| A | 91 | Pass |
| B | 89 | Pass |
| C | 65 | Pass |
| D | 40 | Fail |

The Decision Tree may build something like this.

```
Marks > 90 ?

       Yes

        A

       No

Marks > 88 ?

      Yes

       B

      No

Marks > 64 ?

      Yes

       C

      No

       D
```

Notice something important.

Every leaf contains only **one student**.

Training Accuracy

```
100%
```

Although the accuracy is perfect on the training dataset, this tree has simply memorized the data.

---

# 3. What is Overfitting?

Suppose a new student appears.

```
Marks = 87
```

The tree has never seen this value before.

Since it memorized the training examples instead of learning general patterns, its prediction may be poor.

This problem is called

```
Overfitting
```

Definition

> **Overfitting occurs when a model learns the training data too well, including its noise and small details, resulting in poor performance on unseen data.**

---

## Real-Life Analogy

Imagine two students preparing for an exam.

### Student A

Memorizes all previous question papers.

### Student B

Understands the concepts.

If the exam contains new questions,

Student B performs much better.

Decision Trees should behave like Student B.

---

# 4. Stopping Criterion 1: Pure Node

The simplest stopping condition.

Suppose after splitting we obtain

```
Yes

Yes

Yes

Yes
```

All samples belong to the same class.

There is no uncertainty.

Gini

```
0
```

Entropy

```
0
```

No further learning is possible.

The algorithm stops.

---

Another example

```
No

No

No
```

Again,

the node is perfectly pure.

Stop.

---

# 5. Stopping Criterion 2: Maximum Depth (max_depth)

The depth of a tree is simply the number of levels from the root node.

Example

```
Root

↓

Level 1

↓

Level 2

↓

Level 3

↓

Level 4
```

Suppose

```
max_depth = 3
```

The tree becomes

```
Level 1

↓

Level 2

↓

Level 3

↓

STOP
```

Even if the node is still impure,

the algorithm stops growing.

---

## Why Use max_depth?

Suppose

```
Depth = 50
```

The tree becomes extremely large.

It memorizes the training data.

Now suppose

```
Depth = 2
```

The tree becomes too small.

It misses important patterns.

This is called

```
Underfitting
```

Therefore,

`max_depth` controls the complexity of the tree.

---

## Example

```python
from sklearn.tree import DecisionTreeClassifier

model = DecisionTreeClassifier(max_depth=4)
```

The tree can never grow beyond four levels.

# 6. Stopping Criterion 3: Minimum Samples Split (min_samples_split)

This parameter checks whether the current node contains enough samples to split.

Suppose

```
Current Node

3 Samples
```

Suppose

```
min_samples_split = 5
```

Rule

A node must contain at least

```
5 samples
```

before splitting.

Since

```
3 < 5
```

the node cannot be split.

It immediately becomes a leaf node.

---

## Why is this useful?

Imagine trying to make a decision using only two data points.

```
+

-
```

There is not enough information to make a reliable split.

`min_samples_split` prevents the tree from making decisions using extremely small datasets.

---

# 7. Stopping Criterion 4: Minimum Samples Leaf (min_samples_leaf)

This parameter is different.

Suppose a split produces

```
Current Node

100 Samples

↓

Split

↓

Left Child

1 Sample

Right Child

99 Samples
```

The left child contains almost no information.

Suppose

```
min_samples_leaf = 5
```

Every leaf node must contain at least

```
5 samples
```

Since

```
1 < 5
```

the split is rejected.

The parent node remains unchanged.

---

## Why is this useful?

Very small leaf nodes often memorize individual training examples.

By forcing every leaf to contain multiple samples,

the model generalizes much better.

---

# 8. Difference Between min_samples_split and min_samples_leaf

Students often confuse these two parameters.

---

## min_samples_split

Checks **before splitting**.

Question

```
Does the current node contain enough samples to split?
```

If No

↓

Stop.

---

## min_samples_leaf

Checks **after splitting**.

Question

```
Will every child node contain enough samples?
```

If any child has too few samples,

↓

Reject the split.

---

## Example

Current Node

```
12 Samples
```

Suppose

```
min_samples_split = 10
```

The node is allowed to split.

After splitting

```
Left Child

2 Samples

Right Child

10 Samples
```

Suppose

```
min_samples_leaf = 5
```

Left child contains only

```
2 samples
```

Therefore,

the split is rejected.

---

# 9. Summary Table

| Hyperparameter | Checks | Purpose |
|----------------|--------|---------|
| Pure Node | Gini = 0 or Entropy = 0 | Stop when node becomes perfectly pure |
| max_depth | Maximum tree height | Prevents excessively deep trees |
| min_samples_split | Samples before splitting | Prevents splitting tiny nodes |
| min_samples_leaf | Samples after splitting | Prevents tiny leaf nodes |

# 10. Complete Stopping Flow

```
Current Node
       │
       ▼

Is Node Pure?
       │
 ┌─────┴─────┐
 │           │
Yes          No
 │           │
 ▼           ▼
Stop    Check Maximum Depth
               │
        ┌──────┴──────┐
        │             │
      Reached       Not Reached
        │             │
        ▼             ▼
      Stop     Check min_samples_split
                      │
               ┌──────┴──────┐
               │             │
         Too Few Samples   Enough Samples
               │             │
               ▼             ▼
             Stop      Try Splitting
                             │
                             ▼
                 Check min_samples_leaf
                             │
                   ┌─────────┴─────────┐
                   │                   │
            Child Too Small      Child Valid
                   │                   │
                   ▼                   ▼
             Reject Split         Accept Split
                                      │
                                      ▼
                              Repeat Recursively
```

# 11. Why Are These Hyperparameters Important?

Without stopping rules,

the Decision Tree

- Becomes extremely deep.
- Memorizes the training data.
- Achieves very high training accuracy.
- Performs poorly on unseen test data.

Stopping criteria improve the model's ability to generalize.

---

# Final Summary

```
Start Building Tree
        │
        ▼

Find Best Split
        │
        ▼

Split Dataset
        │
        ▼

Check Stopping Conditions

• Pure Node?
• Maximum Depth?
• Enough Samples to Split?
• Enough Samples in Every Leaf?
        │
        ▼

If Any Condition is Met

↓

Stop Growing

Else

↓

Split Again

↓

Repeat Recursively

↓

Final Decision Tree
```

# Key Takeaways

- A Decision Tree does **not** grow forever.
- Without stopping rules, the tree overfits by memorizing the training data.
- **Pure Node** stops splitting because all samples belong to one class.
- **max_depth** limits the height of the tree.
- **min_samples_split** requires a minimum number of samples before a node can be split.
- **min_samples_leaf** ensures that every leaf node contains a minimum number of samples after splitting.
- These hyperparameters help control model complexity and improve generalization on unseen data.
