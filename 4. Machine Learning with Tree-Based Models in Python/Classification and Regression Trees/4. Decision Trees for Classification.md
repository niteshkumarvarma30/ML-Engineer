# Concept

## Decision Trees for Classification

Welcome to the world of CART (Classification And Regression Trees)!

Up until now, we have been studying Linear Models (like Logistic Regression and Linear SVMs). Those models learn by calculating massive math equations to draw a single straight line through your data.

Decision Trees do not use math equations. Instead, they play a game of "20 Questions."

---

### 1. The "20 Questions" Game

Imagine you are trying to guess if an animal is a Dog or a Cat. You might ask a sequence of Yes/No (If/Else) questions:
* Is the weight greater than 20 lbs? (If Yes, go left. If No, go right).
* Does it bark? (If Yes, go left. If No, go right).

A Classification Tree does exactly this. It looks at your features and automatically learns the best sequence of if-else questions to split the data into pure categories.

* **The Top:** The tree starts at the top with a single question involving one feature and one split-point (e.g., "Is cell radius <= 0.05?").
* **The Branches:** The data flows down the True or False branches based on the answer.
* **The Ends (Leaves):** Once the data reaches the end of the path, the tree looks at the prevailing class in that bucket and makes its final prediction.

> The maximum number of questions (branches) it takes to get from the top to the bottom is called the **Maximum Depth**.

---

### 2. The Superpowers of Trees

Because Decision Trees play "20 Questions" instead of drawing a straight math line, they have two massive superpowers:

**Superpower A: Capturing Non-Linear Relationships.** 
Trees do not care if your data looks like a bullseye, a checkerboard, or a zig-zag. They can easily classify complex, non-linear data without needing the "Kernel Trick."

**Superpower B: No Scaling Required.** 
Remember how we had to use `StandardScaler` for KNN and SVMs so that big numbers didn't bulldoze small numbers? Decision Trees don't care about distance. The question "Is income > $100,000?" works perfectly fine next to the question "Is age > 2?". You never need to scale your data for a Decision Tree!

---

### 3. Decision Boundaries (Boxes vs. Lines)

If you plot a Decision Tree's boundary on a graph, it looks very different from a Linear Model.

* **Linear Models:** Draw one smooth, diagonal, straight line.
* **Decision Trees:** Draw Rectangular Boxes.

Why rectangles? Because every time a tree asks a question, it only looks at **one single feature at a time**. 
For example, asking "Is Feature X > 5?" draws a perfectly straight vertical wall on the graph. Asking "Is Feature Y < 10?" draws a perfectly straight horizontal wall. When you combine vertical and horizontal walls, you get rectangles!

---

### 4. Cheat Sheet: Python Code

Here is how you build a tree in scikit-learn. Notice the new `stratify` trick when splitting the data!

```python
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import train_test_split
from sklearn.metrics import accuracy_score

# 1. The Stratify Trick
# stratify=y ensures that the Training set and Testing set get the exact 
# same proportion of classes (e.g., 80% Benign, 20% Malignant) as the original data!
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=1)

# 2. Instantiate the Tree
# We set max_depth=2 to stop it from playing too many questions and overfitting!
dt = DecisionTreeClassifier(max_depth=2, random_state=1)

# 3. Fit and Predict
dt.fit(X_train, y_train)
y_pred = dt.predict(X_test)

# 4. Evaluate
print("Accuracy:", accuracy_score(y_test, y_pred))
```
