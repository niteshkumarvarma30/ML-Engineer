# 1. How Good is Your Model? (Classification Metrics)

When thinking back to classification problems, we often use **accuracy** (the fraction of correctly classified labels) to measure model performance. However, accuracy is not always a useful metric. 

## The Problem: Class Imbalance

Consider a model for predicting whether a bank transaction is fraudulent, where **only 1% of transactions are actually fraudulent**. 

If we build a "dumb" model that simply classifies *every single transaction* as legitimate, this model would have an **accuracy of 99%**! However, it does a terrible job of actually predicting fraud, meaning it completely fails at its original purpose. 

This situation, where one class is much more frequent than the other (e.g., legitimate transactions containing way more instances than fraudulent ones), is called **class imbalance**. This is a very common situation in real-world data and requires a different approach to assessing a model's performance.

---

## The Confusion Matrix

Given a binary classifier (like our fraudulent transactions example), we can create a 2-by-2 matrix that summarizes performance. This is called a **confusion matrix**.

Usually, the class of interest is called the **positive class**. Since we aim to detect fraud, the positive class here is a *fraudulent transaction*.

Here is how a confusion matrix is laid out:

| | Predicted: Legitimate (Negative) | Predicted: Fraudulent (Positive) |
| :--- | :--- | :--- |
| **Actual: Legitimate (Negative)** | **True Negative (TN)** | **False Positive (FP)** |
| **Actual: Fraudulent (Positive)** | **False Negative (FN)** | **True Positive (TP)** |

Let's define each quadrant based on our fraud detection example:
* **True Positives (TP):** Fraudulent transactions that were correctly labeled as fraudulent.
* **True Negatives (TN):** Legitimate transactions that were correctly labeled as legitimate.
* **False Positives (FP):** Legitimate transactions that were incorrectly labeled as fraudulent *(Model raised a false alarm)*.
* **False Negatives (FN):** Fraudulent transactions that were incorrectly labeled as legitimate *(Model missed the fraud)*.

---

## Assessing Classification Performance

From the confusion matrix, we can calculate several critical metrics to evaluate our model's true performance.

### 1. Accuracy
Accuracy is simply the sum of true predictions divided by the total sum of the matrix.
$$ \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN} $$

### 2. Precision (Positive Predictive Value)
Precision is the number of true positives divided by the sum of all positive predictions. 

$$ \text{Precision} = \frac{TP}{TP + FP} $$

* **What it means:** Out of all the transactions the model *claimed* were fraudulent, how many actually were?
* **High Precision:** Means a lower false positive rate. Not many legitimate transactions are being falsely accused of fraud.

### 3. Recall (Sensitivity)
Recall is the number of true positives divided by the sum of true positives and false negatives. 

$$ \text{Recall} = \frac{TP}{TP + FN} $$

* **What it means:** Out of all the *actual* fraudulent transactions in the dataset, how many did the model successfully find?
* **High Recall:** Means a lower false negative rate. The model successfully predicted most of the fraudulent transactions correctly.

### 4. F1-Score
The F1-score is the **harmonic mean of precision and recall**. 

* This metric gives equal weight to precision and recall, therefore it factors in both the number of errors made by the model and the *type* of errors. 
* The F1 score favors models with similar precision and recall, and is a useful metric if we are seeking a model which performs reasonably well across both metrics, especially when dealing with imbalanced datasets.

---

## Confusion Matrix in scikit-learn

Scikit-learn provides built-in functions to easily compute the confusion matrix and a comprehensive classification report containing all these metrics.

```python
from sklearn.metrics import classification_report, confusion_matrix
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import train_test_split

# Instantiate the classifier
knn = KNeighborsClassifier(n_neighbors=7)

# Split the data
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.4, random_state=42)

# Fit the training data
knn.fit(X_train, y_train)

# Predict the labels of the test set
y_pred = knn.predict(X_test)

# 1. Generate the Confusion Matrix
print(confusion_matrix(y_test, y_pred))

# 2. Generate the Classification Report
print(classification_report(y_test, y_pred))
```

### Understanding the Output

* **`confusion_matrix()`**: Outputs the 2x2 array showing your TN, FP, FN, and TP counts.
* **`classification_report()`**: Outputs a formatted text report showing the Precision, Recall, F1-Score, and Support (the number of actual occurrences of the class in the dataset) for *each* class.

Here is an example of what the `classification_report` output looks like:
