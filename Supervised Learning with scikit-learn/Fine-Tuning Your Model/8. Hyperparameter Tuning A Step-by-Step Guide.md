# Hyperparameter Tuning: A Step-by-Step Guide

## 1. What is a Hyperparameter?

In machine learning, there are parameters that the model learns on its own during training (like the coefficients $\beta$ in linear regression).

However, there are other settings that the model cannot learn. You, the data scientist, must set these manually before the model starts training. These are called **Hyperparameters**.

*Examples:* The `alpha` value in Ridge/Lasso Regression, or the `n_neighbors` (K) in a KNN model.

## 2. What is Hyperparameter Tuning?

Since you don't know the perfect hyperparameters in advance, you have to guess and check. Hyperparameter Tuning is the process of trying out many different hyperparameter values, evaluating how well each one performs, and keeping the best ones.

### The Golden Rule of Tuning:

When you are testing dozens of different hyperparameters, you are at a high risk of overfitting to your test data. To prevent this, you must:

1. Split your data into a Training Set and a Test Set.
2. Put the Test Set in a vault and do not touch it.
3. Perform your tuning using Cross-Validation (CV) entirely on the Training Set.
4. Once you find the perfect hyperparameters, use them to evaluate your model on the untouched Test Set one final time.

## 3. Method 1: Grid Search Cross-Validation (GridSearchCV)

Grid Search is the brute-force method of hyperparameter tuning.

You create a "grid" (a dictionary) of all the possible values you want to test. The algorithm will then exhaustively test every single possible combination of those values using k-fold cross-validation.

*Example:* If you want to test 4 different `n_neighbors` values and 2 different metrics (Euclidean vs. Manhattan), Grid Search will test all 8 possible combinations.

**How to do it in scikit-learn:**
* Import `GridSearchCV` from `sklearn.model_selection`.
* Create a dictionary: `param_grid = {'n_neighbors': [2, 5, 8, 11], 'metric': ['euclidean', 'manhattan']}`
* Pass your model and the `param_grid` into `GridSearchCV` and call `.fit()`.
* You can see the winning combination by calling `model.best_params_` and `model.best_score_`.

**The Problem with Grid Search**
It is computationally expensive and does not scale well.
If you want to test 3 hyperparameters, each with 10 possible values, using 10-fold cross-validation, the computer has to fit the model 10,000 times ($10 \times 10 \times 10 \times 10$). This can take hours or even days on large datasets.

## 4. Method 2: Randomized Search (RandomizedSearchCV)

To solve the computational nightmare of Grid Search, we use Random Search.

Instead of testing every single combination, you specify how many iterations you want to run (e.g., `n_iter = 10`). The algorithm will randomly pick 10 combinations from your grid and test only those.

*Why it's great:* It saves a massive amount of time and computing power. Surprisingly, randomly sampling the grid is often just as good at finding the optimal (or near-optimal) hyperparameters as an exhaustive Grid Search.

**How to do it in scikit-learn:**
It works exactly like `GridSearchCV`, but you import `RandomizedSearchCV` instead and pass in the `n_iter` argument to tell it how many random combinations to try.

## 5. The Final Step

Once `GridSearchCV` or `RandomizedSearchCV` finishes running, it automatically saves the best version of your model. You can immediately pass your untouched Test Set into the `.score(X_test, y_test)` method to see how well your newly optimized model performs on unseen data!

# How Hyperparameter Combinations Work

To understand how Grid Search calculates combinations, let's look at a real-world example before we look at the machine learning code.

## 1. The Ice Cream Shop Analogy

Imagine you are at an ice cream shop and you are allowed to build a sundae. You have to pick exactly one item from three different categories:

* **Size (2 options):** Small, Large
* **Flavor (3 options):** Vanilla, Chocolate, Strawberry
* **Syrup (2 options):** Caramel, Fudge

How many totally unique sundaes can you build? To find out, you multiply the number of options together: **2 x 3 x 2 = 12 total combinations.**

Here are the first few sundaes you could make:
* Small + Vanilla + Caramel
* Small + Vanilla + Fudge
* Small + Chocolate + Caramel
* Small + Chocolate + Fudge
*(...and so on, until you reach 12).*

## 2. Applying this to Machine Learning (GridSearchCV)

In the Python code example, we gave the computer a "menu" of hyperparameters to choose from. This menu was our `param_grid`:

```python
param_grid = {
    'n_neighbors': [3, 5, 7, 9, 11],               # 5 options
    'weights': ['uniform', 'distance'],            # 2 options
    'metric': ['euclidean', 'manhattan', 'minkowski'] # 3 options
}
```

Just like the ice cream sundae, Grid Search is going to build every single unique "recipe" (model) possible using this menu.

Because there are 5 neighbors, 2 weights, and 3 metrics, we multiply them:
**5 x 2 x 3 = 30 unique combinations.**

Here is exactly what the computer is doing behind the scenes. It starts building models:

* **Model 1:** n_neighbors=3, weights='uniform', metric='euclidean'
* **Model 2:** n_neighbors=3, weights='uniform', metric='manhattan'
* **Model 3:** n_neighbors=3, weights='uniform', metric='minkowski'
* **Model 4:** n_neighbors=3, weights='distance', metric='euclidean'
*(...it keeps swapping out ingredients until it builds all 30 unique models).*

## 3. Why are there "150 total fits" then?

You might remember the code printed out: *"30 total combinations x 5-fold CV = 150 total fits!"*

Here is why: Cross-Validation (CV) means the model tests itself multiple times to be absolutely sure it is accurate. Because we chose 5-fold CV, the computer has to take Model 1 and test it 5 separate times on different chunks of the data.

So:
* 30 unique model recipes
* Each recipe is tested 5 times
* **30 x 5 = 150 total training runs.**

## 4. The Problem (and why RandomizedSearchCV exists)

30 combinations is easy for a computer. But what if you wanted to test a massive grid?

* 10 options for parameter A
* 10 options for parameter B
* 10 options for parameter C
* 10 options for parameter D

That is **10 x 10 x 10 x 10 = 10,000 combinations.**
If you use 5-fold cross-validation, the computer has to train the model **50,000 times!** This could take days.

`RandomizedSearchCV` solves this by saying: *"Instead of testing all 10,000 combinations, I'm just going to randomly pick 50 combinations from the menu and test those."* It saves a massive amount of time and usually finds a model that is just as good!
