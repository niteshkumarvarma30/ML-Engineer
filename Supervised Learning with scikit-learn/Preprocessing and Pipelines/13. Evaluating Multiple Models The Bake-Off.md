# Evaluating Multiple Models: The "Bake-Off"

When you start a new machine learning project, you rarely know which algorithm will perform best. Instead of guessing, data scientists run a "bake-off"—testing several models out-of-the-box to see which one shows the most promise before spending hours tuning it.

Here is how you decide which models to invite to the bake-off, and how to judge the winner.

## 1. Guiding Principles for Choosing Models

You don't need to test every single model in existence. You can narrow down your list based on three factors:

* **Size of the Dataset:**
  * If you have a massive amount of data, you can use complex, data-hungry models like Artificial Neural Networks.
  * If you have fewer features or a smaller dataset, simpler models (like Logistic Regression) will train much faster and are less likely to overfit.

* **Interpretability (The "Why"):**
  * If you are predicting something high-stakes (like loan approvals or medical diagnoses), stakeholders will ask why the model made a specific prediction.
  * Models like Linear/Logistic Regression and Decision Trees are highly interpretable (you can easily read the coefficients or follow the tree's logic).

* **Flexibility:**
  * Flexible models (like KNN or Random Forests) make very few assumptions about your data. They don't assume the data follows a straight line (linear relationship). They can capture highly complex patterns, but they are often harder to interpret.

## 2. The Golden Rule of Comparison: Scale First!

Before you compare models, you must scale your data (e.g., using `StandardScaler`).

Why? Because models like KNN (which uses physical distance) and Logistic Regression (which uses mathematical coefficients) will completely fail on unscaled data. If you don't scale the data first, your comparison is rigged—Decision Trees (which don't care about scaling) will look artificially better than KNN.

## 3. How to Run the Comparison

Instead of testing one model at a time, we use Python dictionaries and a `for` loop to test them all simultaneously.

1. **Pick a Metric**: Decide what success looks like (e.g., Accuracy for classification, RMSE for regression).
2. **Create a Dictionary**: Store the models you want to test.
   ```python
   models = {"Logistic Regression": LogisticRegression(), "KNN": KNeighborsClassifier(), "Decision Tree": DecisionTreeClassifier()}
   ```
3. **Loop and Cross-Validate**: Loop through the dictionary. For every model, run a `cross_val_score` using the same KFold splits on your Training Data.
4. **Save the Results**: Append the cross-validation scores to a list so you can graph them.

## 4. Judging the Winner (The Boxplot)

The absolute best way to compare models is by visualizing their Cross-Validation scores using a Boxplot (as seen in your screenshot).

Here is how to read the boxplot:
* **The Orange Line (Median)**: This is the middle score for the model across all the cross-validation folds. The model with the highest orange line is usually the winner.
* **The Box (Spread)**: A short, tight box means the model is highly consistent. A massive, tall box means the model is unstable (it scored really well on some folds, but terribly on others).
* **The Winner**: In your screenshot, Logistic Regression is the clear winner. It has the highest median accuracy (around 84.5%), and its box is relatively tight, meaning it performs consistently well across different cuts of the data.

Once you declare a winner using the Training Data, you can finally evaluate that single winning model on your untouched Test Data to get your final, real-world accuracy score!

# Are the Evaluation Steps Always the Same?

Let's break down how the "bake-off" comparison steps change across the different branches of machine learning.

## 1. Classification vs. Regression (Supervised Learning)

**The Steps: EXACTLY THE SAME!**

Because Classification and Regression are both types of Supervised Learning (meaning you have a target column `y` with the correct answers), the workflow is identical.

You still:
* Split the data (`train_test_split`)
* Scale the features (`StandardScaler`)
* Put the models in a dictionary and loop through them.
* Use Cross-Validation (`cross_val_score`)

**The ONLY thing that changes is the Metric:**
* **For Classification**: You grade the test using Accuracy or ROC AUC.
* **For Regression**: You grade the test using RMSE (Root Mean Squared Error) or R-Squared. (You can't use "Accuracy" because predicting a house costs $300,001 instead of $300,000 isn't "wrong", it's just off by $1).

## 2. Supervised vs. Unsupervised Learning

**The Steps: COMPLETELY DIFFERENT!**

Unsupervised Learning (like Clustering or Dimensionality Reduction) is a totally different world because there is no target `y` column. You are just feeding the computer raw data (`X`) and asking it to find hidden patterns.

Because there is no "answer key", you cannot use `train_test_split`, and you cannot use `cross_val_score`. *(You can't grade an exam if you don't know the answers yourself!)*

**How do you evaluate Unsupervised Models then?**
Instead of checking answers, you measure the *shape* of the patterns the model found.

*Example (K-Means Clustering)*: If you ask the model to group your customers into 3 clusters, you evaluate it by measuring how tightly packed the clusters are, and how far apart they are from each other (using metrics like Inertia or the Silhouette Score).

## Summary

* **Supervised (Classification/Regression)**: Same code, same workflow, just change the scoring metric!
* **Unsupervised**: Totally different workflow. No `y` variable, no cross-validation, and entirely different math to judge success.

```python
import matplotlib.pyplot as plt
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import cross_val_score, KFold, train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier

# (Assuming 'music_df' is already loaded in your environment)

# Split the data FIRST to prevent data leakage
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

# Scale the data (fit_transform on train, ONLY transform on test)
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)

# 2. Build the Dictionary of Models
models = {
    "Logistic Regression": LogisticRegression(), 
    "KNN": KNeighborsClassifier(),
    "Decision Tree": DecisionTreeClassifier()
}

# 3. Cross-Validation Loop (The "Bake-Off")
results = []

for model in models.values():
    # Setup the K-Fold strategy
    kf = KFold(n_splits=6, random_state=42, shuffle=True)
    
    # Run the cross-validation using the SCALED training data
    cv_results = cross_val_score(model, X_train_scaled, y_train, cv=kf)
    
    # Save the scores to our list
    results.append(cv_results)

# 4. Visualize the Results
# This creates a boxplot so we can see which model has the highest median and best consistency
plt.boxplot(results, labels=models.keys())
plt.title("Cross-Validation Accuracy Comparison")
plt.ylabel("Accuracy")
plt.show()

# 5. Final Evaluation on the Untouched Test Set
print("--- Final Test Set Performance ---")
for name, model in models.items():
    # Train the model on the full training set
    model.fit(X_train_scaled, y_train)
    
    # Grade it on the hidden test set
    test_score = model.score(X_test_scaled, y_test)
    
    print("{} Test Set Accuracy: {:.3f}".format(name, test_score))
```
