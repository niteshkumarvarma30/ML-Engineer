# Word Embeddings

In our previous lessons, we used Bag-of-Words (BoW) and TF-IDF to turn text into math.
While these tools are great for basic counting, they have a massive, fundamental flaw: They are completely blind to actual meaning.

Let's look at how Word Embeddings fix this flaw by teaching computers how to actually "understand" language!

## 1. The Problem: Blind Counting

![Blind Counting 1](../../images/Screenshot%202026-07-20%20121211.png)
![Blind Counting 2](../../images/Screenshot%202026-07-20%20121313.png)

If you have two sentences—"I love this movie" and "I love this film"—a human knows these mean the exact same thing.

However, to BoW or TF-IDF, the words "movie" and "film" are treated as two completely distinct, unrelated columns in a spreadsheet. They have absolutely nothing to do with each other. If a model learns that "movie" is a positive word, it won't automatically know that "film" is also a positive word.

### The Comparison Table

Here is exactly how a computer sees the difference between the two approaches:

| Word | BoW / TF-IDF Format (Blind) | Embedding Format (Meaningful) |
| :--- | :--- | :--- |
| Movie | `[1, 0, 0, 0, 0, 0]` | `[ 0.85, -0.42, 0.91, 0.11 ... ]` |
| Film | `[0, 1, 0, 0, 0, 0]` | `[ 0.82, -0.39, 0.88, 0.15 ... ]` |
| King | `[0, 0, 1, 0, 0, 0]` | `[-0.99,  0.88, -0.12, 0.76 ... ]` |

*   **Notice the BoW column:** The 1s and 0s just tell you if the word is there or not. "Movie" and "Film" share zero similarities.
*   **Notice the Embedding column:** The math arrays (vectors) for "Movie" and "Film" are almost exactly the same numbers! The computer mathematically recognizes that they are highly related concepts!

## 2. What are Embeddings? (The GPS Analogy)

![GPS Analogy](../../images/Screenshot%202026-07-20%20121341.png)

Word Embeddings are literally GPS coordinates for language.

Imagine a giant, multi-dimensional map of every word in the English dictionary.
Just like the cities of Paris and Lyon sit right next to each other on a map of France, the words "car" and "bus" will be plotted right next to each other on the mathematical map of language.

**How do they learn this?** The algorithm reads millions of books and articles. It starts by assigning random coordinates to every word. Then, it plays a game of "fill in the blank" (predicting missing words in sentences). As it learns, it slowly physically moves the words around the map. Words that frequently hang out in the same sentences eventually cluster together!

## 3. Using the Gensim Library

![Gensim Library 1](../../images/Screenshot%202026-07-20%20121400.png)
![Gensim Library 2](../../images/Screenshot%202026-07-20%20121430.png)

You do not have to train these maps yourself (which takes supercomputers weeks to do). Google and Stanford already did the heavy lifting and uploaded their maps for free!

We use a Python library called `gensim` to download and explore these maps (models like Word2Vec and GloVe).

```python
import gensim.downloader as api

# 1. Download/Load a pre-trained map (GloVe)
# "wiki-gigaword" means it was trained by reading all of Wikipedia.
# "50" means it uses 50-dimensional math (50 coordinates per word).
model = api.load('glove-wiki-gigaword-50')

# 2. Look up the exact GPS coordinates for a word!
print(model['movie'])
# Output: [ 0.308, 0.172, -0.233, 0.023 ... ] (An array of 50 numbers!)
```

## 4. Measuring Similarity

![Measuring Similarity 1](../../images/Screenshot%202026-07-20%20121447.png)
![Measuring Similarity 2](../../images/Screenshot%202026-07-20%20121503.png)

Because these words are just points on a map, we can use simple math (Cosine Similarity) to measure the exact physical distance between them!

Gensim gives us two amazing, built-in tools for this:

**A. How close are these two specific words?**
```python
similarity = model.similarity("film", "movie")
print(similarity)
# Output: 0.931 (Meaning these two words are 93.1% identical!)
```

**B. What are the closest neighbors to this word?**
```python
# Look around the map and find the 3 closest words to "movie"
similar_to_movie = model.most_similar('movie', topn=3)
print(similar_to_movie)
# Output: [('movies', 0.932), ('film', 0.931), ('films', 0.893)]
```

## 5. Visualizing the Map with PCA

![Visualizing PCA 1](../../images/Screenshot%202026-07-20%20121545.png)
![Visualizing PCA 2](../../images/Screenshot%202026-07-20%20121559.png)

It is impossible for human eyes to look at a 50-Dimensional graph.
To actually see the clusters of words on our screen, we must use PCA (Principal Component Analysis).

PCA acts like a shadow-caster. It mathematically squishes those 50 dimensions down onto a flat, 2D piece of paper, while carefully preserving the distances between the words.

### The Visual Proof
If you look at the scatter plots in the final screenshots, the magic of Embeddings becomes undeniable:
*   "cat" and "dog" form their own distinct cluster on the left.
*   "movie" and "film" are grouped tightly together at the bottom.
*   "car" and "bus" are clustered off to the right.

### Does the model choice matter?
If you compare the Word2Vec map to the GloVe map, the overall shapes look slightly different, and the absolute coordinates change. **But the relationships never change!** No matter which pre-trained map you download, "movie" and "film" will always find each other.
