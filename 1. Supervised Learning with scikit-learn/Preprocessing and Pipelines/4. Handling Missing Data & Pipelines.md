# Handling Missing Data & Pipelines

When building machine learning models on real-world data, you will inevitably encounter missing values (represented in Python as `NaN` or "Not a Number"). Because scikit-learn models will crash if they see missing data, you must handle it before training.

You generally have two options: **Drop it** or **Impute it**.

## 1. Option 1: Dropping Missing Data

If a feature is only missing a tiny fraction of its data (usually less than 5%), the easiest and safest approach is to simply delete those rows.

* **How:** Use Pandas' `.dropna()` method.
* **Example:** `df.dropna(subset=["genre", "popularity"])` will delete any row that has a blank cell in either the `genre` or `popularity` column.
* **Pros/Cons:** It is fast and easy, but if you drop too much data, your model won't have enough examples to learn from.

## 2. Option 2: Imputation (Making an Educated Guess)

If you are missing a lot of data, you cannot afford to throw those rows away. Instead, you impute (guess) the missing values.

* **For Numeric Data** (like Age or Price): You usually fill in the blank cells with the **mean (average)** or **median** of that column.
* **For Categorical Data** (like Color or Genre): You cannot calculate an average color. Instead, you fill in the blanks with the most frequent category (the **mode**).

In scikit-learn, we use a tool called `SimpleImputer` to do this automatically.

## 3. The Golden Rule: Prevent "Data Leakage"

You **MUST** split your data into Training and Testing sets **BEFORE** you impute.

Imagine you are a teacher grading a test, and you lost one student's test score. To guess their score, you decide to use the class average. If you use the average of every student in the entire school (including the final exam data you aren't supposed to look at yet), you are cheating. You are letting future/hidden data leak into your current calculations.

* **The Fix:** You use `.fit_transform()` on the **Training Data** (this calculates the average and fills the blanks). Then, you use `.transform()` on the **Test Data** (this fills the test set blanks using the Training Data's average, keeping the test data completely blind/unseen).

## 4. The Pro Move: Using Pipelines

Doing this manually (splitting data, imputing numbers, imputing categories, gluing it all back together, training a model) gets very messy and requires a lot of code.

To solve this, scikit-learn gives us **Pipelines**.
A Pipeline is an object that glues multiple steps together into a single workflow.

Instead of calling `imputer.fit()` and then `model.fit()`, you just put them in a Pipeline:
```python
steps = [("imputation", SimpleImputer()), ("model", LogisticRegression())]
```

When you call `pipeline.fit()`, it automatically pushes the data through the imputer, cleans it, and feeds it directly into the model. Best of all, it handles the math perfectly during cross-validation so you never have to worry about Data Leakage!


# Imputer and Pipeline in Machine Learning

## 1. What Does an Imputer Do?

An **Imputer** handles missing values in a dataset.

For example:

| Age | Salary | Experience |
| --: | -----: | ---------: |
|  22 |  30000 |          1 |
|  25 |  40000 |          2 |
| NaN |  50000 |          3 |
|  30 |    NaN |          5 |

`NaN` means that the value is missing.

Many machine learning algorithms cannot directly work with missing values, so we need to replace them with appropriate values.

---

# 2. `SimpleImputer`

Scikit-learn provides `SimpleImputer` for handling missing values.

```python
from sklearn.impute import SimpleImputer

imputer = SimpleImputer(strategy="mean")
```

With `strategy="mean"`, the imputer replaces missing values with the mean of the available values.

For example:

```text
Age:
22, 25, NaN, 30
```

The mean is:

[
\mu = \frac{22+25+30}{3}
]

[
\mu = 25.67
]

Therefore:

```text
Before:
22, 25, NaN, 30

After:
22, 25, 25.67, 30
```

So:

> **Imputer = handles missing data.**

---

# 3. Common Imputation Strategies

`SimpleImputer` provides several strategies.

### Mean

```python
SimpleImputer(strategy="mean")
```

Replaces missing values with the column mean.

### Median

```python
SimpleImputer(strategy="median")
```

Replaces missing values with the column median.

Median is often useful when the feature contains outliers.

### Most Frequent

```python
SimpleImputer(strategy="most_frequent")
```

Replaces missing values with the most frequently occurring value.

This can also be useful for categorical data.

### Constant

```python
SimpleImputer(strategy="constant", fill_value=0)
```

Replaces missing values with a fixed value.

---

# 4. Why Does Imputation Need to Happen After the Train/Test Split?

An imputer **learns information from the data**.

For example, with:

```python
SimpleImputer(strategy="mean")
```

the imputer needs to calculate the mean.

Therefore, we should not do:

```text
Entire Dataset
      ↓
Calculate mean
      ↓
Impute
      ↓
Train/Test Split
```

Because the test data could influence the calculated mean.

This creates **data leakage**.

Instead:

```text
Dataset
   ↓
Train/Test Split
   ↓
Training              Test
   ↓                     ↓
Fit imputer             Don't fit
   ↓                     ↓
Transform               Transform
```

The imputer learns its statistics **only from the training data**.

---

# 5. `fit()` vs `transform()`

This distinction is very important.

## `fit()`

`fit()` means:

> **Learn the required parameters from the data.**

For an imputer, this could mean learning:

* Mean
* Median
* Most frequent value

For a scaler, it means learning:

* Mean
* Standard deviation

---

## `transform()`

`transform()` means:

> **Use the parameters that were already learned.**

For example:

```python
imputer.fit(X_train)

X_train = imputer.transform(X_train)
X_test = imputer.transform(X_test)
```

The imputer learns from `X_train` and then uses those learned values for both datasets.

---

# 6. What Is a Pipeline?

A **Pipeline** combines multiple machine learning steps into one workflow.

Suppose we need to perform:

```text
Missing values
      ↓
Scaling
      ↓
KNN
```

Without a pipeline, we might manually write:

```python
imputer.fit(X_train)

X_train = imputer.transform(X_train)
X_test = imputer.transform(X_test)

scaler.fit(X_train)

X_train = scaler.transform(X_train)
X_test = scaler.transform(X_test)

knn.fit(X_train, y_train)

y_pred = knn.predict(X_test)
```

This works, but there are many separate operations to manage.

---

# 7. Using a Pipeline

We can combine everything:

```python
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="mean")),
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier())
])
```

The pipeline represents:

```text
X
│
▼
┌─────────────────┐
│     Imputer     │
│ Handle missing  │
│     values      │
└────────┬────────┘
         ↓
┌─────────────────┐
│     Scaler      │
│ Standardize     │
│    features     │
└────────┬────────┘
         ↓
┌─────────────────┐
│       KNN       │
│      Model      │
└─────────────────┘
```

Now we can simply write:

```python
pipeline.fit(X_train, y_train)
```

and:

```python
y_pred = pipeline.predict(X_test)
```

---

# 8. What Happens During `fit()`?

When we execute:

```python
pipeline.fit(X_train, y_train)
```

the pipeline performs the steps in order:

```text
X_train
   ↓
Imputer
   ↓
Learn missing-value replacement
   ↓
Transform X_train
   ↓
Scaler
   ↓
Learn mean and standard deviation
   ↓
Transform X_train
   ↓
KNN
   ↓
Train model
```

So the pipeline automatically manages the sequence.

---

# 9. What Happens During `predict()`?

When we execute:

```python
pipeline.predict(X_test)
```

the pipeline does:

```text
X_test
   ↓
Imputer
   ↓
Use training-fitted imputer
   ↓
Scaler
   ↓
Use training-fitted scaler
   ↓
KNN
   ↓
Prediction
```

The imputer and scaler **do not learn anything new from the test data**.

They use the parameters learned during training.

---

# 10. Why Is Pipeline Especially Useful with Cross-Validation?

This is one of the biggest advantages of a Pipeline.

Suppose we use 5-fold cross-validation:

```text
Training Data
      ↓
5-Fold Cross Validation
```

We don't want the imputer or scaler to calculate their statistics using the validation fold.

Instead, for each fold:

```text
Fold
│
├── Training portion
│      ↓
│   Fit Imputer
│      ↓
│   Fit Scaler
│      ↓
│   Train Model
│
└── Validation portion
       ↓
   Transform only
       ↓
   Evaluate Model
```

The Pipeline makes this process automatic.

Therefore, it helps prevent **data leakage during cross-validation**.

---

# 11. Pipeline + GridSearchCV

Pipeline is especially useful with `GridSearchCV`.

For example:

```python
from sklearn.model_selection import GridSearchCV

pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="mean")),
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier())
])

parameters = {
    "knn__n_neighbors": [3, 5, 7, 9]
}

grid = GridSearchCV(
    pipeline,
    param_grid=parameters,
    cv=5
)

grid.fit(X_train, y_train)
```

The double underscore:

```text
knn__n_neighbors
```

means:

```text
Pipeline step → knn
Parameter     → n_neighbors
```

This allows `GridSearchCV` to search the model's hyperparameters while keeping preprocessing inside the cross-validation process.

---

# 12. Complete Workflow

A common machine learning workflow is:

```text
                 Dataset
                    ↓
             Train/Test Split
                    ↓
          ┌─────────┴─────────┐
          ↓                   ↓
       Training              Test
          ↓                   ↓
       Pipeline             Pipeline
          ↓                   ↓
       Imputer               Imputer
          ↓                   ↓
       Scaler                Scaler
          ↓                   ↓
        Model                   │
          ↓                     │
       Training                 │
          │                     │
          └─────────┬───────────┘
                    ↓
               Prediction
                    ↓
             Evaluate Model
```

The important point is that the preprocessing parameters are learned from the training data.

---

# 13. Why Do We Need Both Imputer and Scaler?

They solve different problems.

### Imputer

Handles:

```text
NaN
Missing values
```

### Scaler

Handles:

```text
Different feature scales
```

For example:

```text
Age          → 18–80
Salary       → 20,000–2,000,000
Experience   → 0–30
```

The scaler puts these numerical features onto a comparable scale.

---

# 14. Their Roles

| Component        | Purpose                                                      |
| ---------------- | ------------------------------------------------------------ |
| **Imputer**      | Handles missing values                                       |
| **Scaler**       | Puts numerical features on a comparable scale                |
| **Pipeline**     | Combines preprocessing and model steps                       |
| **GridSearchCV** | Searches for the best hyperparameters using cross-validation |

---

# 15. The Big Picture

A typical ML pipeline can look like:

```text
Raw Data
   ↓
Train/Test Split
   ↓
Imputer
   ↓
Scaler
   ↓
Feature Engineering / Other preprocessing
   ↓
ML Model
   ↓
Prediction
   ↓
Evaluation
```

The Pipeline acts as the **container that keeps these operations together in the correct order**.

---

# 16. Most Important Rules to Remember

### Rule 1

> **Split the data before fitting preprocessing.**

### Rule 2

> **Fit the imputer only on training data.**

### Rule 3

> **Fit the scaler only on training data.**

### Rule 4

> **Use the same fitted imputer and scaler to transform test data.**

### Rule 5

> **Use a Pipeline when multiple preprocessing steps and a model need to work together.**

### Rule 6

> **Pipeline is particularly important with Cross-Validation and GridSearchCV because it prevents preprocessing leakage between folds.**

---

Remember:

```text
Split
  ↓

```

```text
Imputer  → Fix missing values
```
